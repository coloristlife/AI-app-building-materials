 Amazon Simple Storage Service (S3)
  S3 is frequently targeted by attackers, and misconfigurations here are one of the leading causes of massive cloud data breaches. 



Here is the categorized security review questionnaire:

### Access Control and Identity Management

- **Question:** Are the account-level and bucket-level "Block Public Access" (BPA) settings enabled?
  - **Recommended Control:** Enable Amazon S3 Block Public Access (BPA) at the account level to ensure no bucket can be made public, unless the bucket is explicitly designed to host public-facing web assets. 
  - **Associated Risk:** Accidental exposure of sensitive data to the public internet, leading to a catastrophic data breach and regulatory penalties.

- **Question:** Are Bucket Policies configured using the principle of least privilege, and are legacy Access Control Lists (ACLs) disabled?
  - **Recommended Control:** Enforce strict IAM policies and S3 Bucket Policies using condition keys. Enable the "Bucket Owner Enforced" setting in S3 Object Ownership to completely disable legacy S3 ACLs, centralizing access control in IAM.
  - **Associated Risk:** Overly permissive access via complex or conflicting ACLs and policies, allowing unauthorized internal or external users to view, modify, or exfiltrate data.

- **Question:** Are cross-account permissions strictly controlled and audited?
  - **Recommended Control:** Ensure cross-account access is explicitly defined in the bucket policy using the `aws:PrincipalOrgID` condition key to restrict access only to principals within your specific AWS Organization.
  - **Associated Risk:** The "confused deputy" problem or unauthorized cross-account access, allowing malicious actors in external AWS accounts to access or modify your data.

### Data Protection and Encryption

- **Question:** Is Server-Side Encryption (SSE) enforced for all objects stored within the S3 bucket?
  - **Recommended Control:** Enable default bucket encryption using SSE-KMS (AWS Key Management Service) with Customer Managed Keys (CMKs). This ensures granular key rotation policies and allows you to enforce separation of duties (e.g., users need both S3 access and KMS decrypt permissions).
  - **Associated Risk:** Data exposure if the underlying physical storage medium is compromised, or if an attacker gains S3 read access but lacks the necessary KMS key permissions.

- **Question:** Is access to the S3 bucket restricted to secure transport protocols only?
  - **Recommended Control:** Implement a bucket policy with the `aws:SecureTransport` condition key set to `true` to mandate TLS 1.2 or higher for all API requests (PUT, GET, etc.).
  - **Associated Risk:** Interception of data in transit (Man-in-the-Middle attacks) over unencrypted HTTP connections, leading to data theft or modification.

### Network Security and Perimeter Defense

- **Question:** Is access to the S3 bucket restricted to trusted network boundaries, such as specific Virtual Private Clouds (VPCs)?
  - **Recommended Control:** Configure VPC Endpoints (Gateway or Interface Endpoints) for S3 and implement bucket policies using `aws:sourceVpce` or `aws:sourceVpc` condition keys to block any traffic originating from outside the corporate VPC.
  - **Associated Risk:** Exposure of the S3 API to the public internet, increasing the attack surface to credential stuffing or leaked access keys being utilized from remote, unauthorized IP addresses.

### Resilience, Integrity, and Recovery

- **Question:** Is S3 Object Versioning enabled, and is MFA Delete configured for highly sensitive buckets?
  - **Recommended Control:** Enable S3 Versioning to preserve, retrieve, and restore every version of every object. Enforce MFA Delete (Multi-Factor Authentication) to require a hardware or virtual token for permanently deleting an object version or suspending versioning.
  - **Associated Risk:** Irreversible data loss or operational disruption caused by accidental deletion, malicious internal actors, or ransomware attacks overwriting data.

- **Question:** Are critical, compliance-bound objects protected against premature deletion or tampering using Write-Once-Read-Many (WORM) models?
  - **Recommended Control:** Enable S3 Object Lock in Governance or Compliance mode (depending on regulatory requirements) with a defined retention period to strictly prevent object modification or deletion.
  - **Associated Risk:** Tampering or deletion of critical audit logs, financial records, or regulated data, leading to compliance violations, legal penalties, and loss of non-repudiation.

### Logging, Monitoring, and Auditing

- **Question:** Are S3 Server Access Logging and AWS CloudTrail Data Events enabled and centrally monitored?
  - **Recommended Control:** Enable S3 Server Access Logging to an isolated, centralized log bucket. Additionally, enable CloudTrail Data Events for critical buckets to capture detailed object-level API activity. Integrate these logs with a SIEM or Amazon GuardDuty.
  - **Associated Risk:** Lack of visibility and auditability, making it impossible to detect anomalous behavior, investigate unauthorized access, or forensically analyze a data exfiltration event.

- **Question:** Is there an automated mechanism to discover, classify, and alert on sensitive data (e.g., PII, PHI, Secrets) stored in the bucket?
  - **Recommended Control:** Integrate Amazon Macie to continuously scan, classify, and report on sensitive data stored in S3 buckets, and configure automated alerts for high-risk data findings.
  - **Associated Risk:** Developers or automated systems unknowingly dumping highly sensitive data into improperly secured buckets, drastically increasing the blast radius and severity of a potential breach.

### Lifecycle and Data Management

- **Question:** Are S3 Lifecycle policies implemented to manage data retention, archival, and secure disposal?
  - **Recommended Control:** Configure S3 Lifecycle rules to automatically transition older data to colder, cheaper storage (e.g., S3 Glacier) and permanently expire/delete data that exceeds the organization's legal retention requirements.
  - **Associated Risk:** Unbounded accumulation of sensitive data ("data hoarding"), which increases the organizational attack surface, legal discovery liabilities, and unnecessary storage costs.
