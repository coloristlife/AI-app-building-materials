# Obsidian 属性完全指南：全面解析与使用技巧

在 Obsidian 中，[# 属性](https://obsidian.md/zh/help/properties) （Properties）是一项极其强大的功能。然而，大多数 Obsidian 用户并不真正清楚该如何利用笔记顶部的那块元数据（metadata）区域。

在这篇文章中，我将带你详细了解 Obsidian 中提供的每一种属性类型。我会确切地解释它们各自的工作原理，并向你展示在何处使用哪种类型，以帮助你最大化地挖掘笔记和想法的价值。

阅读完本文后，你将拥有一份清晰的路线图，能够将对个人知识管理（Personal Knowledge Management）系统产生最大影响的属性类型真正落地应用。

## 什么是属性（Properties）？

简而言之，属性就是附加在你笔记上的**结构化元数据**。这些元数据通常以纯文本的形式存储在 Markdown 文件本身当中，并以YAML格式显示在 Obsidian 笔记的顶部， 在 [编辑与预览笔记]( https://obsidian.md/zh/help/edit-and-read ) 切换到**编辑模式**的**源码模式**，就可以看到YAML格式的属性配置内容，比如下面的例子，其中“属性”是文档的标题：
![[Pasted image 20260809154524.png]]

对应在非**源码模式**下，对应的属性配置显示如下：
![[Pasted image 20260809154425.png]]
这些属性非常灵活，可以通过一些极其强大的方式帮助你对信息进行组织、排序、过滤和查询。

在 Obsidian 中，属性的运作原理完全相同。唯一的区别在于，Obsidian 的这一切都是建立在**纯文本文件**之上的。这意味着，如果将来你想把笔记转移到其他系统或应用程序中，完全没有任何问题。

## 如何添加属性

在 Obsidian 中，属性的运作原理完全相同。唯一的区别在于，Obsidian 的这一切都是建立在**纯文本文件**之上的。这意味着你的数据极其自由和便携。
  
**💡 核心提示：双重编辑方式**
*   **纯文本编辑（源码模式操作）**：在底层，这些属性完全由 YAML 语法驱动。你可以直接打开源码模式（Source mode），通过手写文本代码的方式来编辑这些属性，这为批量修改和复杂格式提供了极大的灵活性。

*   **可视化界面编辑（UI 操作）**：在 Obsidian 默认的视图下，属性会呈现为一个干净、直观的表格界面。你可以直接点击下拉菜单、日期选择器或复选框来进行可视化编辑，非常适合不想接触代码的用户。

### 纯文本编辑（源码模式操作）

要在 Obsidian 笔记中添加属性，只需在笔记的**最顶部**输入 `---`（三个连字符）。这会在笔记顶部创建一个“属性”区块（顶部和底部都是三个连字符）。接着，你只需直接输入你想要创建的属性名称即可。
注意：如果想用这个方法在中央区域的笔记顶部编辑属性区块，首先需要按照 [编辑与预览笔记]( https://obsidian.md/zh/help/edit-and-read ) 切换到**编辑模式**下的**源码模式**。
> 点击中央区域的笔记顶部的状态栏中的交互式状态图标 ![lucide-book-icon.svg > icon](https://publish-01.obsidian.md/access/cf01a21839823cd6cbe18031acf708c0/Attachments/icons/lucide-book-icon.svg)，然后选择**源码模式**。

如果这个方法不起作用，请检查你的设置是否配置正确。进入 **设置 (Settings) → 选项 (General) → 编辑器 (Editor)**，滚动到“显示 (Display)”部分，确保 **笔记属性(Properties in document)** 设置为 **显示 (Visible)**。
![[Pasted image 20260809113523.png]]

这里的其他选项还包括：**隐藏 (Hidden)**（将属性从笔记中完全隐藏）和 **源码 (Source)**（仅显示原始的 YAML 格式）。

通过这种整齐的排版，无论是你（人类）还是 Obsidian 等软件（电脑），都能一眼看懂并轻松管理这些信息的档案。

### 可视化界面编辑（UI 操作）

如果想通过**图形化界面**添加属性，你需要进入 **设置 (Settings) → 核心插件 (Core plugins)**，确保 **属性列表 (Properties View)** 选项已开启。
![[Pasted image 20260809115156.png]]

严格来说，你不开启它也能直接通过上面的纯文本编辑方式使用属性，但开启后，你可以在用户界面右侧边栏中查看和编辑当前文件的属性，也能浏览你整个库中所有属性的列表（具体操作参见“如何添加属性”章节）。完成这一步后，你就可以开始为你的 Obsidian 笔记添加属性了。

首先需要通过设置在用户界面右侧边栏显示文件属性面板，你可以通过按下 `⌘` 和`p`（Mac）或 `⌃` 和`p`（Windows）打开命令面板，输入“属性”找到并选择 **属性列表：显示当前笔记的属性列表**和**属性列表：显示所有笔记属性**这两个选项。

![[Pasted image 20260809114011.png]]

完成设置后，你可以在用户界面的右侧边栏看到两个属性相关的图标：

- **文件属性**：用于查看和管理当前文件的属性，对应下图最右侧的图标。
- **所有属性**：用于查看和管理当前仓库中的全部属性，对应下图中间的图标。

点击相应图标，即可打开对应的属性视图。

![[Pasted image 20260809114859.png]]

点击相应图标你就可以在右侧边栏面板里与属性进行交互。
一旦你添加了一个属性，你会发现它由两部分组成：
1. **属性名称（或称之为键 / key）**
2. **属性值（value）**

这两者组合在一起构成了所谓的**键值对 (key-value pair)**。你可以直接在笔记界面中创建和设置**属性：

1. **添加一个新属性**
在笔记顶部的属性区域中，选择添加属性。首次创建属性时，先选择一个**属性名称**。例如，可以暂时选择“别名”作为**属性名称**。
   
2. **输入属性名称**
 在**属性名称**输入框中，输入你需要的属性名称，例如“作者”“状态”“发布日期”等。
  
3. **设置属性类型**
创建**属性名称**后，可以通过**属性名称**左侧的图标上点击右键修改**属性类型**。根据需要选择相应的类型，  例如“文本”“列表”“数字”“复选框”“日期”或“日期与时间”。

![[Pasted image 20260809162319.png]]
   
4. **填写属性值**
 确定**属性类型**后，在对应的值输入区域中填写内容。不同的属性类型会提供相应的编辑方式，例如日期类型会使用日期选择器，复选框类型则显示为复选框。
   

> **提示：** **属性名称**和**属性类型**是两个不同的概念。属性名称决定“这个属性叫什么”，属性类型决定“这个属性应该存储什么类型的数据”。因此，创建属性时，可以先建立属性名称，再根据实际用途调整属性类型。


关于属性，最酷的一点是：尽管它们可以在你的笔记顶部或者右侧边栏面板显示为一个漂亮、整洁的用户界面，但它们实际上**是以纯文本形式存储的**。这意味着你的笔记依然具有极强的便携性，如果将来你需要从 Obsidian 迁移，其他工具同样能够读取。虽然这种可视化的属性界面是相对较新的功能，但这种“前言（frontmatter）”的格式，实际上正是 Obsidian 从一开始就支持的 YAML 格式元数据。

## 属性的类型与深度用例解析
  下面我们将详细拆解 Obsidian 中的属性类型。我将结合真实用例，并为你展示它们在底层纯文本（YAML）中是如何呈现的。  

### 1. 文本（Text）

用于标题、作者、状态等自由格式的字符串。这是默认的属性类型，非常灵活。  
**底层纯文本 (YAML) 示例**：

```yaml

作者: "Ada Lovelace"
状态: "进行中"
链接:
  - "[[链接]]"    
  - "[[链接2]]"    
备注: |
可以使用 YAML 块标量来表示多行文本。
在缩进结束之前，每一行都会被保留。
```


**📋 Tips / 提示** ：
*  如果文本中包含标点符号或冒号，请务必用引号将文本括起来。
*  在底层文本中，内部链接会被自动加上双引号。
*  如果需要多行描述，可以使用块标量符号（即 |），这样每一行的缩进和换行都会被完美保留。

### 2. 数字（Number）
用于任何你打算进行数字排序或计算的内容。它的值字段只能输入纯数字（支持整数和小数，不支持表达式）。

**可视化操作与用例**：
*   **每日问题打分**：我将数字属性用于每日笔记模板，记录我的习惯得分。在界面上使用数字属性，可以确保我不小心按到非数字键时，错误的值不会被记录。

**底层纯文本 (YAML) 示例**：

```yaml
priority: 1
estimate_hours: 12.5
```

 **📋 Tips / 提示**：

*   如果你希望系统将其严格视为数字进行处理，**请不要**在数字外面加引号。
  
### 3. 复选框（Checkbox / Boolean）

一个简单的 真/假 (true/false) 切换开关。  

**可视化操作与用例**：

*  **习惯跟踪**：在实时预览或阅读模式下，它显示为一个可以直接点击勾选的小方框。我用它在每日笔记模板顶部打卡，数据随后展示在我的习惯跟踪仪表板（Habit Tracking Dashboard）上。空白框代表 `false`，打钩代表 `true`，未设置则显示为破折号。

  ![[Pasted image 20260809155030.png]]

**底层纯文本 (YAML) 示例**：

```yaml
完成: false
已归档: true
```

**📋 Tips / 提示**：

*   在源码层面，YAML 会识别小写的 `true` 和 `false` 作为布尔值（booleans）。

 
### 4. 日期与时间（Date and Datetime）

用于跟踪事物的创建时间、到期时间或更新时间。  

**可视化操作与用例**：

在界面上，点击它会唤出一个极其直观的日历选择器。

- **Date (日期)**：用于记录某件事情发生、计划或截止的日期。它特别适合用于项目截止日期、发布日期、会议日期、任务日期等需要按“哪一天”进行管理的信息。日期属性还可以与 **Daily notes（日记）** 联动，开启日记插件后，日期可以直接跳转到对应日期的每日笔记；同时，也可以在 **Bases 视图**中按照日期进行筛选、排序和展示。

- **Date & Time (日期与时间)**：用于记录某件事情发生或完成的具体日期和时间。当你不仅需要知道“哪一天”，还需要知道“具体几点”时，就应该使用这种属性。例如，它可以用于记录创建时间、更新时间、审核时间、会议时间或其他需要精确到时间点的信息。这样，你就可以根据时间先后进行筛选、排序，或者判断某项内容距离上次操作已经过去了多久。  

**底层纯文本 (YAML) 示例**：

```yaml
创建: 2025-08-24
会议时间: 2025-08-24T14:30:00
```

对应的属性界面显示：
![[Pasted image 20260809160350.png]]

### 5. 列表（List / Multi-value）
当同一属性需要包含多个值时使用。在界面中，按下 `Enter` 键即可将输入文字变成独立的标签，带有 `x` 按钮可随时删除。**注意：列表属性中不支持标准网址，但支持带引号的内部链接。**
 
**底层纯文本 (YAML) 示例**：
你有两种方式在纯文本中编写列表：
*区块列表 (Block list) 格式*：
```yaml
利益相关方1:
  - 鲍勃
  - 爱丽丝
```

*内联列表 (Inline list) 格式*：
```yaml
利益相关方2: [鲍勃, 爱丽丝]
```

对应的属性界面显示：
![[Pasted image 20260809160820.png]]

**📋 Tips / 提示**：
*  非常适合用于标签（tags）、别名（aliases）和 cssclasses。
*  内联样式和区块样式在功能上是完全等效的，为了保持一致性，建议你在库中只选择其中一种来使用。

### 6. 链接与文件引用（Links to notes and files）
用于存储与其他笔记的关联，或者作为附件文件。

**可视化操作与用例**：
在界面的属性类型设置中，选择 **Text（文本）** 类型，这样 Obsidian 的界面就会直接将这些值视为可交互的链接。

**底层纯文本 (YAML) 示例**：
```yaml
相关联:
  - "[[数据库]]"
  - "[[仓库]]"
```

对应的属性界面显示：
![[Pasted image 20260809161350.png]]

 **📋 Tips / 提示**： 
*   在纯文本 YAML 中编写时，请务必使用引号将 wiki 链接（即双中括号 `[[ ]]`）包裹起来，以避免解析错误。也可以使用URL， 比如https://example.com/docs/overview，来引用你想关联的外部文档
  

## 默认属性（Default Properties）
Obsidian 内置了三种默认属性。请注意，它们的**名称全部是复数形式**（单数的 `tag`/`alias`/`cssclass` 已被废弃，无法正常工作）。

**Tags（标签）**：这是一个特殊的列表属性，横跨整个 Obsidian。可以使用标签对内容进行分类和归属标记。例如，可以根据内容来源、项目、主题或用途设置不同的标签，这样就能方便地区分不同类型的内容，并在需要时快速筛选和查找。
在 Obsidian 中，可以通过 **标签视图（Tags view）** 查看和管理仓库中的标签，并点击标签快速找到使用该标签的笔记。

   **底层纯文本 (YAML) 示例** ：
```yaml
tags:
- 项目
- 规划
- 项目/移动端
```

**📋 Tips**: `tags` 属性使用列表格式，每个标签单独列出。标签还可以使用 `/` 创建层级关系，例如 `项目/移动端` 表示 `移动端` 是 `项目` 下的嵌套标签。这样可以更有条理地组织和筛选相关内容。

**Aliases（别名）**：别名是你创建链接时用来引用该笔记的**附加名称**。通常，我们在 Obsidian 中通过把笔记标题放在两个方括号之间来链接笔记，笔记标题也会显示在反向链接和传出链接的“未链接提及 (Unlinked Mentions)”区域。但如果你给笔记添加了别名，当你使用双括号进行链接，或者在“未链接提及”中查找时，你实际上都可以使用这个别名。只要是列在笔记别名属性里的名称，在链接时都可以被检索到。

**CSS Classes（CSS 类）**：用于单篇笔记的个性化排版。
 如果你在库中添加了任何 CSS 代码片段（snippets），并在外观设置中激活了它们，你就可以通过 `cssClasses` 属性调用相应的类名，将这些片段的样式应用到单篇笔记上。这等于告诉 Obsidian 在渲染这篇笔记时应用哪些特殊的代码。

**操作步骤**：
	要添加 CSS 片段，请前往 **设置 (Settings) → 外观 (Appearance) → CSS 代码片段 (CSS snippets)**，然后打开隐藏的 `Snippets` 文件夹。将你的 CSS 文件放入该文件夹，返回 Obsidian 并重新加载列表。当你看到列表里出现该片段时，打开它的开关。

只要你在 CSS 文件中正确设置了类名，随后在笔记的 `cssclasses` 属性中输入该类名，就能激活对应的样式。
  

## 规则与最佳实践
为了防止你的属性系统变得一团糟，请务必遵循以下规则与实践：

### 核心规则

1. **保持一致（Be Consistent）**：如果你打算将某个属性用于某种用途，请确保每次都以相同的方式使用它。否则你的属性搜索将毫无意义。

2. **要具体（Be Specific）**：由于界面会根据你的历史输入进行自动提示，为不同的工作流使用不同属性名是个好习惯。例如，将视频和通讯状态拆分为 `视频_状态` 和 `通讯_状态`，这样自动补全列表就不会相互干扰。

3. **节制使用（Use Sparingly）**：少即是多。并非每篇笔记都需要属性，但每篇拥有属性的笔记，都应该具体地为你服务。

  
### 最佳实践

1. **尽可能默认使用单数形式的属性名**：防止造成重复（例如 `rating` 和 `ratings`）。**唯一的例外是**允许包含多个值的“列表（List）”属性（例如默认的 tags / aliases）。在这种情况下，使用复数名称可以作为一种直观的提示。

2. **命名属性时不要使用空格**：技术上可行，但不建议。为了确保与其他文本编辑器的兼容性以及未来迁移的便利性，请保持命名连贯（Obsidian 虽然会将大小写 `Book` 和 `book` 视为同一种，但保持统一依然是最佳策略）。

3. **充分利用自动补全功能**：在界面输入时多依靠下拉列表，避免拼错单词导致重复。

4. **全局重命名**：如果你犯了错，或者想更改属性名，打开命令面板的 **属性视图：显示所有属性 (Properties View: Show All Properties)**，在右侧边栏**右键点击**需要更改的属性并选择 **重命名 (Rename)**。这将会在整个库中全局更新！

  

**终极建议：**

在 Obsidian 中使用属性的最完美方式，就是**将它们写死到你的模板（Templates）文件中**。这样当你新建笔记时，不仅不需要死记硬背复杂的 YAML 代码，所有应该存在的界面字段也都已准备就绪，格式分毫不差。
