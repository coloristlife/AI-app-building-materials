`addsumtech/slides_maker` 是一个开源的 AI 驱动工具（基于 MIT 协议），旨在将学术论文、代码仓库、文档甚至仅仅是一个主题，转化为**原生且完全可编辑的 PowerPoint (.pptx) 演示文稿**。它主要作为插件运行在 Codex 或 Claude Code 中，也可以在 ChatGPT（通过 GPT Store）等平台中使用。

与市面上那些“一键生成、为了快而牺牲质量、把文字贴成不可编辑图片”的 AI PPT 工具不同，`slides_maker` 更加严谨，专注于生成可以用于正式答辩、学术会议或商业路演的高质量 PPT。

以下是该项目的核心功能和特色介绍：

### 1. 核心功能与亮点
*   **忠于源文件，拒绝幻觉 (Reads your source)**：它会完整阅读你提供的 PDF 论文、代码仓库（从 README 开始）或各类文档。如果没有素材，它会先联网进行搜索研究。它保证 PPT 中的每一个数据和图表都追溯到你的原始材料，绝不会为了填满页面而凭空捏造数据。
*   **原生且完全可编辑 (Native Editable PPTX)**：生成的 PPT 不是一张张扁平的截图，而是真实的 PPT 对象。里面的文本框、形状、原生图表（可以双击修改数据）以及排版好的数学公式，都可以直接在 PowerPoint 或 Keynote 中点击并重新编辑。甚至论文里的图片也会直接从 PDF 中裁剪并保留，而不是重新绘制。
*   **自带演讲稿与动画设置 (Speaker Notes & Animations)**：它会为每一页 PPT 生成完整的演讲稿并放在备注栏中，方便你上台直接使用。同时，它也会根据需要自动规划“点击出现（Click-build）”的逐步展现动画，并且你可以决定是否需要动画。
*   **多尺寸与多平台适配 (Any Canvas)**：除了常见的 16:9，它还支持重新排版为 4:3 比例、1:1 方形、3:4 的小红书图文卡片、9:16 的 Story 封面或是 A4 打印单页，每个尺寸都有自己独立的布局逻辑和安全区。

### 2. 独特的“多 Agent”架构与独立审核机制
`slides_maker` 并不是通过一个庞大的 Prompt 试图完成所有事，而是将任务分包给了一个“Agent 专业团队”，每个 Agent 职责独立，避免“自己给自己打分”：
*   **内容规划师 (Content-planner)**：作为主编，负责阅读理解并决定每页 PPT 的论点、证据和叙事弧线，确保关键信息没有被遗漏。
*   **设计总监 (Slide-design)**：决定排版、配色、排版节奏和动画。它会根据内容从头设计页面，而不是死板地往模板里倒文字。
*   **独立评论员 (Critic)**：在交付文件前，独立的 Review 机制会试图“挑刺”（如：排版太挤、对比度太弱、数据跟原文对不上），并把问题打回要求修改。
*   **仲裁者 (Arbiter)**：在处理高规格/高风险的 PPT 时，还会引入第二重独立检查来确认 Critic 发现的问题是否属实。

### 3. 工作流程 (How it works)
1.  **简短的访谈**：启动后，它会询问你一些问题：受众是谁？演讲多长时间？是现场演讲还是供人阅读？风格是什么？（如果在赶时间，你也可以让它自己决定）
2.  **阅读与规划**：Agent 阅读你的材料后，会在聊天窗口输出一个每页内容的草稿以及视觉设计方案让你确认。
3.  **构建与布局检查**：根据代码生成 PPTX，并在构建时进行自动化的排版重叠、溢出等格式检查。
4.  **审查与交付**：由 Critic 进行评价和修正，全部通过后才最终交付一个干净的 PPTX 文件到你的电脑本地。

### 4. 适用场景
*   **学术研究**：组会汇报、论文带读、学术会议宣讲、毕业答辩、实验报告（特别擅长处理论文里的公式、图表和结论）。
*   **技术与工程**：代码仓库走查（Repo walkthrough）、架构讲解、工程进度汇报。
*   **商业与产品**：产品发布会（Keynote）、市场数据分析、融资路演（Pitch deck）、公司介绍。
*   **自媒体与分享**：小红书图文卡片、读书分享、知识科普。

总之，`slides_maker` 是一个设计理念非常硬核的生产力工具。它把重点放在了**逻辑梳理、真实度核查以及后期可编辑性**上，致力于帮你完成“阅读材料-提炼大纲-基础排版”这些最耗时的脏活累活，最后交给你一份能拿来精修的专业汇报文件。

# 背后工具使用
`addsumtech/slides_maker` 作为一个高度专业化的 AI PPT 代理工具，其背后依赖了一套非常具体的工程技术栈和多智能体（Multi-Agent）架构。

根据该项目的代码仓库和官方说明，它背后主要使用了以下几类核心工具和技术：

### 1. 核心编程语言与开发框架
*   **Python (99.9%)**：该项目的核心逻辑绝大部分由 Python 编写。
*   **Agent Skill 架构**：它本身并不是一个独立带 UI 的重型软件，而是被设计成一个 **Agent Skill（智能体技能插件）**。它可以被直接注入到大模型编程环境（如 **Claude Code** 和 **Codex**）中运行。这意味着它将底层的 LLM（如 Claude 3.5/3.7 Sonnet 或 GPT-4o）作为它的“大脑”来调用。
*   **包管理与快速分发**：支持通过 `npx skills add addsumtech/slides_maker` 直接进行轻量级（约1.1MB）的快速安装部署。

### 2. 原生 PPTX 结构生成
*   与很多用网页前端（如 HTML2Canvas）截图并贴到 PPT 的工具不同，它被归类为 **“PPTX-native” (原生可编辑 PPTX)** 方案。
*   在 Python 生态中，通常底层依赖于 `python-pptx` 等库，或者直接操作 Office Open XML 规范来构建 PPT。通过这种方式，它能将大模型吐出的数据，精准映射为 PPT 里的原生文本框、真实图表（自带底层 Excel 数据）、数学公式以及点击展现（click-build）动画。

### 3. 关键的“物理级”系统依赖 (用于排版验证与渲染)
为了实现其独有的**自动布局审核与纠错（Critic 角色）**，它在生成 PPTX 文件时需要调用操作系统底层的渲染引擎，以防文字溢出或元素重叠。它背后强依赖以下三个系统工具：
*   **LibreOffice**：用于在后台（Headless 模式）无头渲染 PPT 页面。通过渲染出页面，Critic Agent 可以通过像素/几何坐标去检查排版是否越界、字体是否有问题、甚至文件是否损坏（如果 LibreOffice 打不开，说明文件有错，会在交付给用户前自动修复）。
*   **SVG 栅格化工具 (SVG Rasterizer)**：如 `librsvg`、`cairosvg` 或无头 Chrome/Edge 浏览器，专门用来处理 PPT 中的矢量图标和矢量图表的渲染。

### 4. 多智能体编排 (Multi-Agent Orchestration)
在工具链之上，它在架构上使用了“职责分离”的多 Agent 编排模式：
*   不是用单一的巨大 Prompt 来直接输出内容，而是拆分为独立的工作流脚本：内容规划师（读取源文件、提炼大纲）、设计师（分配排版）、独立批评家（Critic，负责用上文提到的 LibreOffice 检查格式并打回重做）。

### 5. 跨平台宿主工具 (Host Platforms)
除了在本地终端运行（通过 Python 3.9+ 依赖），这个 Repo 的底层工具链也被打包发布到了各大主流 AI 平台上。包括：
*   **ChatGPT / GPT Store** (被称为 addsum studio)
*   **Tencent SkillHub (腾讯)**、**Coze (扣子)** 以及 **ClawHub**

**总结：**
`slides_maker` 本质上是一个以 **Python** 为核心的命令行插件。它利用 **LLM 环境（Claude Code / Codex）** 作为大脑，使用**原生 Office XML/PPTX 读写库**构建元素，并且巧妙地借助 **LibreOffice 和 SVG 渲染器** 在交付前充当“物理视觉检查员”，从而实现高质量的 PPT 生成。
