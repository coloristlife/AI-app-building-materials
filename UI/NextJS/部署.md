经过前面所有的学习，我们已经开发好了一个功能强大、性能强悍的全栈 Next.js 应用。

最后临门一脚：**如何把写好的 Next.js 项目部署到公网上，让全世界的用户都能访问？**

部署 Next.js 主要有 **3 种主流方案**。根据你的项目类型（个人项目、公司服务器、纯静态网站），你可以选择最适合你的部署方式。

---

### 部署前的通用检查清单（Checklist）

无论你选择哪种部署方式，部署前务必在本地运行一次：

```bash
npm run build
```

1.  **检查类型与代码错误：** 确保没有 TypeScript 或 ESLint 报错阻断打包。
2.  **整理环境变量：** 梳理本地 `.env.local` 里的环境变量（如数据库地址 `DATABASE_URL`、密钥 `SECRET`），准备在云平台上配置它们。

### 方案一：Vercel 部署（官方首选，零配置，全功能开挂）⭐️⭐️⭐️⭐️⭐️

**Vercel** 是 Next.js 母公司官方推出的云平台。它是部署 Next.js **体验最好、最简单、性能最狂暴**的方式。

#### 为什么选 Vercel？
*   **全功能原生支持：** 100% 完美支持 Server Components、Server Actions、PPR、ISR、缓存、中间件等所有黑科技。
*   **全球 CDN 边缘加速：** 自动把静态资源和页面推送到全球离用户最近的 CDN 节点。
*   **自动化 Git 部署：** 只要你向 GitHub 提交代码，Vercel 会自动帮你打包部署！

#### 部署流程（只需 3 步，全程 2 分钟）：
1.  **把代码推送到 Git 仓库**（GitHub / GitLab / Bitbucket）。
2.  打开 [Vercel 官网 (vercel.com)](https://vercel.com/) 注册并绑定 GitHub 账号。
3.  点击 **"Add New" ➔ "Project"**，选择你的 Next.js 仓库，在 **Environment Variables** 里填入你的环境变量（如数据库地址），点击 **"Deploy"**！

完成！Vercel 会自动给你分配一个免费的域名（如 `my-app.vercel.app`），并配置好 HTTPS 证书。

### 方案二：自建服务器 / 容器化部署（Docker / Node.js VPS）

如果你们公司有自己的服务器（如阿里云、腾讯云、AWS、DigitalOcean），或者对数据隐私有要求，不能部署在国外云平台上，选择自建服务器。

#### 💡 神级优化配置：开启 Standalone 模式（极小化打包）
在自建服务器或用 Docker 打包时，如果你直接把整个 `node_modules` 传上去，镜像体积动辄 1GB+。

Next.js 官方内置了一个**体积优化黑科技：`output: 'standalone'`**。

在 `next.config.mjs` 中加上这一行：

```javascript
// next.config.mjs
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'standalone', // 开启独立打包模式！
};

export default nextConfig;
```

运行 `npm run build` 后，Next.js 会在 `.next/standalone` 目录下提取出一个**精简版的最小运行包**（把没用到的依赖全部剔除，体积从 1GB 直接缩减到 100MB 左右！）。

#### 自建服务器运行命令：
在服务器上，你只需要把 `.next/standalone` 目录和 `public` 静态资源放上去，然后运行：

```bash
# 启动生产服务器
node server.js
```
（通常配合 PM2 或 Docker 守护进程在后台运行，前面挂一层 Nginx 反向代理）。

---

### 方案三：纯静态 HTML 导出（`output: 'export'`）

如果你的项目只是一个**纯静态网站**（比如公司官网、博客、帮助文档），完全用不到数据库和服务端动态功能。

你可以把 Next.js 当成一个单纯的静态网页生成器（SSG）：

在 `next.config.mjs` 中配置：

```javascript
// next.config.mjs
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export', // 导出纯静态 HTML/CSS/JS！
};

export default nextConfig;
```

运行 `npm run build` 后，Next.js 会在根目录下生成一个名为 **`out`** 的文件夹，里面全都是纯粹的静态 HTML/CSS/JS 文件。

#### 部署方式：
你可以把 `out` 文件夹里的内容，直接丢给：
*   **Nginx / Apache** 静态服务器
*   **GitHub Pages / Cloudflare Pages**
*   **阿里云 OSS / AWS S3** 静态存储桶

#### ⚠️ 静态导出的代价（功能限制）：
开启 `output: 'export'` 后，你将**无法使用任何服务端动态功能**：
*   ❌ 无法使用 Server Actions (`'use server'`)
*   ❌ 无法使用动态渲染 API（如 `cookies()`、`headers()`）
*   ❌ 无法使用未缓存的 API 路由 (`route.ts`)
*   ❌ 无法使用增量静态再生 (ISR)

| 维度 | 方案一：Vercel 云部署 | 方案二：Docker / Node.js VPS 自建 | 方案三：纯静态导出 (`out`) |
| :--- | :--- | :--- | :--- |

| **运维成本** | 零运维（官方全包） | 需要自己维护服务器、HTTPS、PM2 | 极低 |
| **适合场景** | 个人项目、SaaS 出海、团队快速验证 | 国内公司项目、私有化部署、数据合规要求高 | 个人博客、产品官网、文档中心 |

### 总结

*   如果你想**省心、快速上线、享受极致性能**：毫不犹豫选择 **Vercel**。
*   如果你要部署在**国内阿里云/腾讯云公司服务器**上：在 `next.config.mjs` 里开启 **`output: 'standalone'`**，用 Docker/PM2 部署。
*   如果你只是做**不需要后端的静态博客/官网**：使用 **`output: 'export'`** 导出静态网页文件挂在 Nginx 上。




当你把一个 Next.js 项目直接连接 GitHub 并点击 "Deploy" 到 Vercel 时，Vercel **默认是不包含数据库本身（数据存储仓库）的**。

那么问题来了：**Vercel 部署出来的到底是什么？它主要帮你托管了什么呢？**

# Vercel 部署
### 一、 Vercel 主要包含什么？（三大核心托管服务）

当你部署项目到 Vercel 时，Vercel 帮你承载的是你的 **“应用程序本身”**（包括前端界面、计算节点和网络传输）。它主要包含以下 3 块：

#### 1. 全球 CDN 网络（托管静态资源与 HTML）
*   **包含内容：** 你的 CSS、JS 代码、图片（`next/image` 自动压缩）、字体，以及打包好的静态 HTML 网页。
*   **作用：** Vercel 在全球几十个国家部署了边缘节点（Edge Network）。用户在东京打开网站，静态资源就从东京节点发给他；在纽约，就从纽约节点发给他，实现**极致秒开**。

#### 2. Serverless Functions（托管后端代码与 Server Actions）
*   **包含内容：** 你的服务端组件（RSC）、Server Actions (`'use server'`)、以及 API 接口 (`route.ts`)。
*   **作用：** 你的后端 Node.js 代码被拆分成了无数个**“无服务器函数（Serverless Lambda）”**。
    *   没有人访问时，CPU 占用为 0（不花钱）。
    *   当有人触发 Server Action 或访问动态页面时，Vercel 会在毫秒级内自动唤醒一个 Node.js 函数去计算结果，算完立刻销毁，支持无限弹性扩容（哪怕突然来几万个人也不卡）。

#### 3. 自动化运维与安全套件
*   免费的域名解析与 **HTTPS 证书（SSL）**。
*   GitHub 提交代码**自动化构建（CI/CD）** 与 PR 预览网址。
*    DDoS 防火墙攻击拦截、实时运行日志（Logs）与性能监控。

---

### 二、 那数据库（Database）怎么办呢？

既然 Vercel 默认不自带数据库，你的数据存哪里？

你有 **两种非常主流的解决方案**：

#### 方案 A：在 Vercel 控制台里一键添加“生态数据库”（最省心）
Vercel 虽然自己不盖数据库机房，但它在后台提供了一个叫 **Storage** 的标签页，和顶级 Serverless 数据库厂商合作，让你在 Vercel 内部**一键生成数据库**：

*   **Vercel Postgres**：Vercel 官方提供的 PostgreSQL 数据库（底层由 Neon 驱动）。
*   **Vercel KV (Redis)**：用来做高频数据缓存、限流、实时排行榜的 Redis 数据库（底层由 Upstash 驱动）。
*   **Vercel Blob**：专门用来存用户上传的头像、大图、视频等文件存储桶。

> 点击“一键创建”后，Vercel 会**自动把 `DATABASE_URL` 环境变量注入到你的项目里**，你甚至不需要手动复制粘贴配置！

#### 方案 B：连接独立的第三方云数据库（最通用）
你完全可以在外面注册一个独立的数据库服务（比如 **Supabase**、阿里云 RDS），拿到连接字符串：
`DATABASE_URL="postgresql://user:password@db.supabase.co:5432/postgres"`

然后把这个字符串手动填入 Vercel 项目设置里的 **Environment Variables（环境变量）** 即可。

当你用 Next.js + Vercel + 云数据库开发时，整体的云端架构是这样的：

### 总结

*   **Vercel** = 你的**“计算与渲染大脑”**（负责跑 Next.js 代码、发网页、跑 Server Actions）。
*   **Supabase / Neon** = 你的**“数据仓库”**（负责安全保存表格和数字）。

它们之间通过一条隐藏在环境变量里的网络连接线（`DATABASE_URL`）紧密配合，构成了现代全栈开发的最强黄金搭档！

### 一、 方案 A 各项服务的免费额度盘点

#### 1. Vercel Postgres（数据库）—— 免费！

#### 2. Vercel KV（Redis 缓存/高频数据）—— 免费！
*   **免费额度：** 包含 **256 MB** 存储空间，以及每天 **30,000 次** 的读写请求。

### 二、 什么时候才需要付费？

只有在以下两种情况下，方案 A 才会涉及费用：

1.  **你的流量或数据量超过了免费额度**：
    比如你的网站突然火了，用户上传了几千张大图把 1GB 的 Blob 存储空间给挤爆了，或者数据库写满了 512MB。
2.  **你绑定了信用卡并主动开启了按量付费（Pay-as-you-go）**：
    超额部分会按照很便宜的单价（比如额外的存储几十分钱 1GB）从信用卡扣费。
