
```tsx

type Props = { // 定义类型：在 Next.js 15+ 中，它们都是 Promise params: Promise<{ slug: string }>; searchParams: Promise<{ lang?: string; page?: string }>; };



export default async function BlogPostPage({ params, searchParams }: Props)
```
这行代码是 Next.js + TypeScript 开发中最经典的一行**页面组件声明**。

如果把它拆开，其实包含了 **JavaScript 基础语法**、**TypeScript 类型校验** 和 **Next.js 专属规则** 5 个部分的组合。

我们把这行代码像剥洋葱一样，一层层拆开来看：


---

### 1. `export default` ➔ 导出主页面（Next.js 规则）
*   **含义**：把这个函数设置为当前文件的“默认导出”。
*   **作用**：Next.js 规定，每个 `page.tsx` 文件里**必须有一个默认导出（export default）**。只有这样，Next.js 才知道当用户访问这个网址时，该把哪个组件展示在屏幕上。

### 2. `async` ➔ 异步函数（Next.js 服务端组件特权）
*   **含义**：声明这是一个**异步函数**。
*   **作用**：有了 `async`，你就可以在函数内部使用 `await` 了！比如去 `await` 查数据库，或者去 `await params` 拿到网址参数。
*   *补充*：在传统的纯 React 客户端组件里，函数组件是不允许写 `async` 的；但在 Next.js 的服务端组件里，写 `async` 是最核心的超能力。

### 3. `function BlogPostPage` ➔ 组件的名字
*   **含义**：这是你给这个 React 组件起的名字。
*   **规则**：React 规定组件名字首字母必须**大写**（大写字母开头才会被识别为 React 组件）。你可以随意起名，比如叫 `ArticlePage` 或 `Detail` 都可以。

### 4. `{ params, searchParams }` ➔ 参数解构（JavaScript 语法）
这是初学者最容易懵的地方。

当用户访问页面时，Next.js 会自动给你的组件传递一个大礼包（一个包含各种页面信息的对象 `props`）。
这个大礼包长这样：`{ params: ..., searchParams: ... }`。

*   **不写解构的写法（比较啰嗦）：**
    ```tsx
    function BlogPostPage(props: Props) {
      // 你每次用都要写 props.xxx
      const params = props.params; 
      const searchParams = props.searchParams;
    }
    ```
*   **写了解构的写法（简化版）：**
    直接用 `{ params, searchParams }` 括号，把大礼包里的 `params` 和 `searchParams` **直接拆出来**当成变量用。

### 5. `: Props` ➔ 类型约束（TypeScript 语法）
*   **含义**：冒号后边的 `Props` 是你提前在上面写好的 TypeScript 类型接口（Interface）。
*   **作用**：告诉 TypeScript 编译器：“请严格按照 `Props` 的规则检查 Next.js 传进来的 `params` 和 `searchParams`，如果类型不对（比如我把数字当成了字符串），请立刻给我画红线报错！”

---

### 💡 总结成一句大白话：

> **“我要导出当前文件的默认主页面（`export default`），这是一个支持异步等待的页面组件（`async function`），名字叫 `BlogPostPage`；请帮我直接把 Next.js 传进来的路径参数 `params` 和查询参数 `searchParams` 剥离出来用（`{...}`），并且请用 `Props` 这个规则来严格检查它们（`: Props`）。”**
