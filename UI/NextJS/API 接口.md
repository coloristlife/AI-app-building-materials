

Next.js 的服务端组件（`page.tsx`）可以像“后厨”一样直接查数据库，然后把**做好的饭菜（HTML 网页）**端给用户。

那如果我不想要完整的网页，我只想要 **纯粹的数据（JSON）** 怎么办？这时候，** API 文件夹（在最新版里叫 Route Handlers，路由处理程序）**就闪亮登场了！

继续用我们那家 **“高级餐厅”**来打比方：

*   **`page.tsx`（服务端页面） = 餐厅的“堂食大厅”。** 客人（浏览器）来这里，你端出去的是摆好盘的精致菜肴（完整的 HTML + CSS 网页）。
*   **`api` 文件夹 = 餐厅的“外卖窗口 / 批发档口”。** 来这里的人不需要你摆盘，他们往往是其他的系统、手机 App、或者你自己的前端代码。你只需要用塑料盒把**半成品生鲜（纯 JSON 数据）** 打包丢给他们就行了。

---

### 1. 在最新的 App Router 中，API 是怎么写的？

在以前的旧版本里，必须要有一个名为 `pages/api` 的文件夹。
但在最新的 App Router 中，规矩变了，变得和写页面一样直观：**文件后缀决定了它的身份。**

*   你想建一个**网页**，文件就必须叫 `page.tsx`。
*   你想建一个**纯数据接口 (API)**，文件就必须叫 **`route.ts`**。

**动手试一试：**
假设你想做一个接口，别人访问 `http://localhost:3000/api/hello`，就能拿到一串打招呼的数据。

你在项目里新建文件夹和文件：`app/api/hello/route.ts`（注意，外层叫 `api` 只是大家的习惯，方便管理，真正的魔法在于 `route.ts` 这个名字）。

```typescript
// app/api/hello/route.ts
import { NextResponse } from 'next/server';

// 规定这个接口只接收 GET 请求
export async function GET() {
  
  // 1. 这里可以写任何后端逻辑：查数据库、读取文件、调用大模型...
  const data = {
    message: "你好！这是来自 Next.js 后厨的外卖！",
    time: new Date().toLocaleTimeString()
  };

  // 2. 不要返回 HTML，而是返回纯 JSON 数据
  return NextResponse.json(data);
}
```

现在，如果你在浏览器里直接访问 `http://localhost:3000/api/hello`，你看到的将不再是网页，而是一串干净的文本（JSON）：
`{"message":"你好！这是来自 Next.js 后厨的外卖！","time":"12:00:00 PM"}`

### 2. 灵魂拷问：既然 `page.tsx` 已经能直接查数据库了，为什么还需要写 API？

很多初学者学到这里都会有一个巨大的困惑：“你前面才夸过服务端组件可以直接 `await db.query()` 拿数据，多爽啊，为什么我现在还要脱裤子放屁去写一个专门的 API 接口？”

这个问题问得极其关键！在 Next.js 里，**如果你只是为了把数据展示在网页上，你确实不需要写 API！** 直接在 `page.tsx` 里查数据就行了。

但是，在以下这 **3 种典型场景**下，你必须建 API 接口（外卖窗口）：

#### 场景一：你有其他平台的客户端（如手机 App、小程序）
你的公司除了有 Next.js 写的网站，还有一个 iOS App 和一个微信小程序。
App 和小程序是**看不懂 HTML 网页的**，它们只需要干净的 JSON 数据（比如商品列表）来自己画界面。这时候，你就得写一个 `app/api/products/route.ts`，充当公共的后端接口给它们调用。

#### 场景二：第三方服务给你发通知（Webhooks）
假设你在网站里接了**支付宝/微信支付**。用户付完钱后，微信的服务器需要悄悄给你的服务器发一条消息：“这哥们付钱了，赶紧给他发货”。
微信服务器不可能去访问你的前端网页，它需要一个纯粹的接收端点。这时候你需要写一个 `POST` 接口：`app/api/payment-notify/route.ts` 来专门接收这种系统级的通知。

#### 场景三：客户端组件的复杂交互（如无限滚动加载）
假设你做了一个像抖音那样的网页，用户向下滑动，会不断加载新的视频。
首次加载的 10 个视频，可以在服务端的 `page.tsx` 里直接查好。但是当用户滑动到底部，触发了**客户端组件**的事件时，客户端组件怎么去要下面 10 个视频的数据？
此时，客户端组件（前厅服务员）就可以通过 `fetch('/api/videos?page=2')`，去向你的 API 接口（外卖窗口）点单。

### 总结：你的全栈武器库

到这里，你已经掌握了 Next.js 全栈开发的全部武器：

1.  **`page.tsx` (服务端组件):** 负责做堂食大餐。直接在服务器查好数据，拼成精美的网页直接端给用户。首选！最快！
2.  **`'use client'` (客户端组件):** 负责前厅服务。专门处理点击、滑动、弹窗等需要用户互动的活儿。
3.  **`route.ts` (API 接口):** 负责外卖窗口。专门给手机 App、第三方服务（如支付回调）、或者复杂的客户端交互提供纯净的 JSON 数据。

这就是为什么大家说 Next.js 是一个**真正的全栈框架**。你根本不需要去隔壁再建一个 Node.js 或 Python 的后端项目，在一个文件夹里，前端界面和后端接口全搞定了！
