在前面我们多次提到过，Next.js App Router 默认所有的组件都是**服务端组件（Server Components）**。

如果你想让某个组件拥有**点击事件、状态变化、或者动画效果**，你就必须显式地把它声明为 **客户端组件（Client Components）**。

声明方式极其简单：**在文件的第一行（必须是第一行）写上 `'use client'`。**

这节课我们来彻底搞懂客户端组件的**底层原理、四大刚需场景、以及最关键的架构最佳实践**。

---

### 1. 破除最大的误区：客户端组件只在浏览器渲染？

很多初学者认为：“服务端组件在服务器跑，客户端组件在浏览器跑。”

**这个理解是不准确的！**

真实情况是：
*   **服务端组件（RSC）：** 100% 只在服务器运行，**代码永远不会发送给浏览器**。
*   **客户端组件（Client Component）：** 
    1.  **在服务端（SSR 阶段）：** 它同样会被服务器预先渲染成静态的 HTML 骨架发给浏览器（让你瞬间看到画面）。
    2.  **在浏览器端（Hydration 水合阶段）：** 浏览器的 JavaScript 脚本下载完毕，像“注入水分”一样把事件监听器（`onClick`）、状态（`useState`）挂载到刚才的静态 HTML 上，让页面恢复交互能力。

---

### 2. 什么时候必须加上 `'use client'`？（四大刚需场景）

只要你的代码里出现了以下 **4 种情况中的任意一种**，你就必须在文件顶部加上 `'use client'`，否则 Next.js 会立刻报错：

#### 场景 1：需要监听用户事件（Event Listeners）
比如：`onClick`、`onChange`、`onSubmit`、`onScroll`、`onKeyDown`。
```tsx
'use client'; // 必须加！因为需要响应用户点击

export default function LikeButton() {
  return <button onClick={() => alert('点了点赞！')}>点赞</button>;
}
```

#### 场景 2：使用了 React 的状态与生命周期 Hooks
比如：`useState`、`useEffect`、`useReducer`、`useRef`、`useContext` 以及你自定义的包含这些 Hook 的函数。
```tsx
'use client'; // 必须加！因为用到了状态和副作用
import { useState, useEffect } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);
  useEffect(() => { console.log('挂载完成'); }, []);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

#### 场景 3：需要调用浏览器专属的 API
比如：`window`、`document`、`localStorage`、`navigator.geolocation`（获取地理位置）。
```tsx
'use client'; // 必须加！因为服务器上根本没有 localStorage 对象

export default function ThemeToggle() {
  const theme = localStorage.getItem('theme');
  return <div>当前主题：{theme}</div>;
}
```

#### 场景 4：使用了依赖浏览器 API 的第三方 React 库
比如：动画库（`framer-motion`）、图表库（`recharts`、`chart.js`）、富文本编辑器（`quill`）等。

---

### 3. 黄金架构法则：“把 `'use client'` 往组件树的底层推”

这是区分 Next.js 高手和新手的核心标志！

#### ❌ 菜鸟做法：直接在页面顶部写 `'use client'`
很多新手为了图省事，发现页面里有个按钮需要 `useState`，就直接在 `app/blog/page.tsx` 第一行加了 `'use client'`。

**后果：** 这个页面里的所有子组件、连同整个页面，**统统失去了 Server Component 的所有优势**（无法直连数据库、打包体积变大、敏感密码不敢写）。

#### ✅ 高手做法：只把有交互的小部件抽离成客户端组件（Push Down）

保持 `page.tsx` 是服务端组件，只把具体的交互按钮抽成小文件：

```text
app/
 └── blog/
      ├── page.tsx            <-- 服务端组件（无 'use client'，负责直接查数据库）
      └── LikeButton.tsx  <-- 客户端组件（有 'use client'，只负责点击点赞）
```

**代码展示：**

```tsx
// app/blog/LikeButton.tsx (客户端组件，专注交互)
'use client';
import { useState } from 'react';

export default function LikeButton() {
  const [likes, setLikes] = useState(0);
  return <button onClick={() => setLikes(likes + 1)}>👍 {likes}</button>;
}

// ----------------------------------------------------

// app/blog/page.tsx (服务端组件，享受极致性能)
import prisma from '@/lib/prisma';
import LikeButton from './LikeButton'; // 引入客户端组件

export default async function BlogPage() {
  // 可以在这里极其安全、快速地查数据库！
  const posts = await prisma.post.findMany();

  return (
    <main className="p-8">
      <h1>博客列表</h1>
      {posts.map(post => (
        <div key={post.id}>
          <h2>{post.title}</h2>
          {/* 把客户端交互组件嵌入进来 */}
          <LikeButton />
        </div>
      ))}
    </main>
  );
}
```

### 4. 高级技巧：如何在客户端组件里嵌套服务端组件？

假设你写了一个客户端弹窗组件 `<Modal />`（里面有关闭按钮，必须是客户端组件），但你希望弹窗里的内容是一个**在服务端查数据库的 Server Component**。

如果你在 `<Modal />` 里直接 `import ServerComponent`，那个 `ServerComponent` 会被**强制降级**为客户端组件！

**正确做法：利用 React 组件组合（Composition，即 `children` 插槽）！**

```tsx
// 1. app/components/Modal.tsx (客户端弹窗容器)
'use client';
import { useState } from 'react';

export default function Modal({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(true);
  if (!isOpen) return null;

  return (
    <div className="modal">
      <button onClick={() => setIsOpen(false)}>关闭</button>
      {/* 2. 通过 children 渲染传进来的服务端组件 */}
      {children}
    </div>
  );
}

// ----------------------------------------------------

// 3. app/page.tsx (服务端页面组件)
import Modal from './components/Modal';
import ServerProfile from './components/ServerProfile'; // 服务端组件

export default function Page() {
  return (
    <Modal>
      {/* 作为 children 传进去，ServerProfile 依然 100% 在服务端运行！ */}
      <ServerProfile />
    </Modal>
  );
}
```

### 💡 总结 Cheat Sheet

1.  **暗号：** 文件第一行 `'use client'`。
2.  **定位：** 负责交互（`onClick`）、状态（`useState`）、浏览器 API（`window`）。
3.  **渲染：** 在服务端先打出静态 HTML，在浏览器端水合（Hydrate）恢复交互。
4.  **法则：** **能用服务端组件就用服务端组件！** 只有需要交互的小局部，才抽出文件加 `'use client'`。

# 组合 Composition

**“组合（Composition）”在代码里其实已经发生了，它就藏在 `children` 这个属性里。**

在 React 中，**“组件组合（Component Composition）”**并没有什么专属的关键字。它的标准定义就是：**把一个组件写在另一个组件的开闭标签中间（`<Parent><Child /></Parent>`），并通过 `children` 属性接收。**

请看当时 `app/page.tsx` 里的那行代码：

```tsx
// 📍 组合（Composition）就发生在 app/page.tsx 的这几行代码里：
export default function Page() {
  return (
    <Modal>
      {/* 👈 这里！你把 ServerProfile 组合（塞）进了 Modal 的标签内部！ */}
      <ServerProfile /> 
    </Modal>
  );
}
```

---

### 为什么这种“组合”写法在 Next.js 里至关重要？

我们通过 **“直接 `import`（非组合）”** 和 **“用 `children`（组合模式）”** 的对比，你就会秒懂：

#### ❌ 非组合写法（直接 `import` ➔ 导致服务端组件失效）

如果你没有用组合模式，而是在 `Modal.tsx` 内部直接去 `import ServerProfile`：

```tsx
// app/components/Modal.tsx
'use client'; // ⚠️ 这是客户端组件边界！

// ❌ 直接 import：把服务端组件引入到了客户端组件文件里
import ServerProfile from './ServerProfile'; 

export default function Modal() {
  return (
    <div className="modal">
      {/* React 会被迫把 ServerProfile 也降级强转成客户端组件！ */}
      <ServerProfile /> 
    </div>
  );
}
```
* **结果：** `ServerProfile` 失去了直连数据库、零打包体积等所有服务端组件的优势，被强行变成了客户端组件。

---

#### ✅ 组合模式写法（使用 `children` ➔ 完美保留服务端组件）

我们不让 `Modal.tsx` 去 `import` 任何服务端组件，而是让它只留一个 **`children` 属性（插槽）**：

```tsx
// 1. app/components/Modal.tsx (客户端组件)
'use client';

// Modal 根本不关心里面放的是啥，它只负责渲染 children 插槽
export default function Modal({ children }: { children: React.ReactNode }) {
  return <div className="modal">{children}</div>;
}

// ----------------------------------------------------

// 2. app/page.tsx (服务端组件)
import Modal from './components/Modal';
import ServerProfile from './components/ServerProfile';

export default function Page() {
  return (
    // ⭐️ 这就是组件组合（Composition）：把 <ServerProfile /> 像塞填料一样塞给 <Modal />
    <Modal>
      <ServerProfile />
    </Modal>
  );
}
```

**ServerProfile 就是一个纯正的服务端组件（Server Component）**。

---

### 为什么“组合模式”能破局？（原理）

当 Next.js 在服务器上运行 `page.tsx` 时：

1. 它会**先**在服务器上把 `<ServerProfile />` 跑完，拿到查数据库后的结果（RSC Payload）。
2. 然后，把这个已经在服务器上渲染好的结果，作为 `children` 参数传给 `<Modal />`。
3. 当页面到了用户的浏览器里，`<Modal />`（客户端组件）开始运行，但它里面的 `children` **早就在服务器上渲染好了**！
