如果说上一次解释的“静态渲染（SSG）”是**提前做好罐头放货架上**，那么 **Dynamic Rendering（动态渲染）** 就是它的完全对立面——**厨师接单后现场现炒**。

---

### 1. 什么是动态渲染（Dynamic Rendering）？

**动态渲染**是指：当用户在浏览器里敲下网址、发起访问请求的**那一个瞬间**，服务器才开始现场执行代码、现场查数据库、现场拼装 HTML 页面发给用户。

*   **静态渲染（Static）**：打包时（Build）渲染一次，所有人看同一份静态文件（0 毫秒开箱即用）。
*   **动态渲染（Dynamic）**：用户访问时（Request）现场渲染，每个人看到的都是**定制化、100% 实时鲜活**的内容。

---

### 2. 什么时候 Next.js 会“自动”切换到动态渲染？

在 Next.js 的 App Router 里，你不需要手动去改很多配置。只要你在 `page.tsx` 里使用了以下**任意一个“动态信号”**，Next.js 就会极其聪明地自动把这个页面切到 **Dynamic Rendering** 模式：

#### 动态信号 1：使用了 `cookies()` 或 `headers()`
你需要知道当前登录的用户是谁、Token 是什么，或者读取用户的 IP 地址。
*   *场景：* `/dashboard`（用户个人后台）。每个人登录后看到的都是自己的隐私数据，不可能提前静态打包。

#### 动态信号 2：使用了 `searchParams`（网址问号参数）
你需要根据用户在网址里输入的 `?search=iphone&page=2` 动态去查数据库。
*   *场景：* `/search`（搜索结果页）。用户的搜索词千奇百怪，不可能提前把所有搜索结果都打包出来。

#### 动态信号 3：使用了未缓存的数据请求（`no-store` 或 Prisma 裸查）
你在 `fetch` 里显式写了 `cache: 'no-store'`，或者直接在服务端组件里用 Prisma 查数据库。
*   *场景：* `/stock-market`（股票/加密货币实时行情）。价格每一秒都在变，必须现场去拉最新数据。

---

### 3. 如何“手动强制”开启动态渲染？

如果你写了一个页面，既没用 Cookies 也没用 `searchParams`，但你就是希望它**每次被访问时都重新查一次数据库**，你可以直接在 `page.tsx` 的最顶部写上一行配置：

```tsx
// app/news/page.tsx

// 核心魔法配置：强制这个页面采用动态渲染（每次请求都现炒）
export const dynamic = 'force-dynamic';

export default async function NewsPage() {
  const news = await getLatestNews();
  return <div>{/* 渲染实时新闻 */}</div>;
}
```

### 4. 动态渲染的“得”与“失” (Trade-offs)

| 维度        | 静态渲染 (Static Rendering) | 动态渲染 (Dynamic Rendering)       |
| :-------- | :---------------------- | :----------------------------- |
| **数据实时性** | ❌ 相对滞后（依赖打包或定时刷新）       | ✅ **100% 实时、绝对鲜活**             |
| **个性化体验** | ❌ 所有用户看一模一样的页面          | ✅ **因人而异**（按当前登录用户展示）          |
| **加载速度**  | ⚡ **爆表极速**（服务器直接发死文件）   | ⏳ **稍慢**（依赖服务器现场查库和渲染时间）       |
| **服务器压力** | 🟢 **极低**（甚至能丢给 CDN 处理） | 🔴 **较高**（每次访问都要消耗 CPU 和数据库连接） |

---

### 💡 终极决策树：我该用哪个？

在开发一个 Next.js 页面时，在心里问自己这个问题：

> **“全网的所有用户，看到的页面内容是一模一样的吗？”**

*   **是 ➔ 静态渲染（Static Rendering）：** 如公司官网、博客文章、帮助文档、隐私协议。
*   **否 / 不确定 ➔ 动态渲染（Dynamic Rendering）：** 如购物车、个人中心、聊天界面、带筛选功能的搜索页。
