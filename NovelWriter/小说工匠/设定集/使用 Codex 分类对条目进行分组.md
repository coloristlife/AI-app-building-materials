
# 使用 Codex 分类对条目进行分组

https://www.novelcrafter.com/courses/ultimate-beginners-guide/grouping-entries-with-codex-categories

**通过将条目组织成自定义的分组和分类，来掌控你日益庞大的 Codex。**


在上一课中，我们使用自定义详情（Custom details）结构化了每个 Codex 条目内部的信息。但是，随着你的 Codex 增长到包含几十个角色和地点，即使是内部结构良好的条目，在外部也需要进行分组。

这就是 **Codex 分类（Categories）** 发挥作用的地方。虽然一个条目只能有一种“类型 (Type)”（比如它要么是“角色”，要么是“地点”），但它可以同时属于任意数量的“分类 (Category)”。

在本课中，我们将创建一个自定义分类，并学习如何将我们的条目打包捆绑在一起。

**核心收获**
*   分类（Categories）可以将相关的 Codex 条目分组，而无需考虑它们的原始“类型”（角色/地点/物品等均可混编）。
*   Codex 条目可以同时属于多个分类。
*   有两种方法可以将条目添加到你的分类中：标签（Tags）和 Codex 详情（Codex details）。

**为什么要使用分类？**
分类可帮助你的 Codex 在不断扩充时保持井然有序。你可以根据当前场景的需要来折叠或展开这些分组，而无需在几十个条目中艰难地滚动查找。

> **作者笔记 (Kate)**
> 在我的舒适推理小说中，我设定了很多村庄居民。当我在写面包店里的场景时，我不需要看到“里弗斯 (Rivers) 家族”的条目把我的侧边栏弄得乱七八糟。分类让我可以把这些条目最小化（折叠），直到我真正需要它们为止。

如果你使用 AI 功能，**整个分类可以一次性被添加到消息的上下文（Context）中**，省去了你手动逐一添加每个条目的麻烦。当你想要将一组条目的背景信息完整地发给 AI 时，这非常有用。你可以为以下内容创建 Codex 分类：
*   家族群体（“里弗斯家族”）
*   派系或组织（“镇议会”、“盗贼公会”）
*   地理位置集群（“格伦福德村”、“首都”）
*   故事弧线（“谋杀案调查”、“爱情支线”）
*   魔法系统或技术（“炼金术”、“星舰组件”）

**创建自定义分类**
让我们为里弗斯家族创建一个分类。这个组将包括几个角色、家族住宅以及一些重要的背景故事。

1.  在 Codex 侧边栏中，点击 **⚙（齿轮图标）** 打开 Codex 设置。*(配图说明：Codex 设置菜单的特写)*
2.  点击 **+ New（新建）** 创建一个新分类。
3.  填写分类详情：
    *   **A. 名称 (Name)**：给你的分类起一个清晰的名字（例如，“里弗斯家族”）。
    *   **B. 颜色 (Color)**：挑选一种颜色帮助它脱颖而出（可选）。
    *   **C. 关联标签 (Associated Tags)**：输入能将条目链接到此分类的标签（例如，“Rivers Family”），或者设置一个关联的“自定义详情”。
    *   **D. 关联类型 (Associated Types)**：选择哪些类型的条目可以出现在这个分类中。如果不确定，请保留全部选中状态。
4.  你的分类会自动保存。

**额外提示**：如果你正在写一个系列小说，自定义分类可以在该系列内的所有书籍之间共享。这意味着你只需要设置一次！

**将条目添加到分类中**
你已经创建了分类，现在让我们来填充它。有两种方法可以添加条目：标签和 Codex 详情。

**方法 1：使用标签**
这是最直接的方法。举个例子，如果你将一个角色打上“嫌疑人”的标签，Novelcrafter 就会自动把他们添加到设置为“关联了嫌疑人标签”的“嫌疑人”分类中。设置方法如下：
1.  打开你想要添加的 Codex 条目（例如，“玛格丽特·里弗斯”）。
2.  在 Tags（标签）部分，输入你为该分类设置的标签（例如，“Rivers”）。*(配图说明：Codex 条目标签部分的特写)*
3.  该条目现在会出现在你的自定义分类中，而不是默认的“类型”区域里。*(配图说明：Codex 侧边栏的特写，显示里弗斯家族分类及其中的条目)*
4.  对你想要包含的每个条目重复此操作。

请记住，条目可以有多个标签，所以同一个角色可以同时出现在“里弗斯家族”和“镇议会”这两个不同的分类中。

**方法 2：使用 Codex 详情**
如果你已经设置了带有“下拉选项 (Dropdown)”的 Codex 详情（正如在“结构化 Codex”那节课中所讲的），你可以利用它自动将条目归入各个分类。

假设我们有一个名为“状态 (Status)”的 Codex 详情，其选项包含这个人是“嫌疑人”、“受害者”还是“证人”。我们可以为“嫌疑人”建立一个分类，并设定：任何“状态”被选为“嫌疑人”的条目，自动归入该分类。
1.  转到设置中的“自定义分类 (Custom Categories)”并选择你的分类。
2.  点击 **Add Detail (添加详情)**。
3.  选择你的 Codex 详情（它必须是下拉菜单类型），并选择相关的选项值。*(配图说明：选择 Codex 详情及其对应值的界面特写)*
4.  现在，任何具有该详情值的条目都会自动出现在该分类中。

**将分类与 AI 结合使用**
除了方便整理之外，分类在与 AI 协作时也极其强大。

在之前的课程中，我们讨论了上下文（Context）——即当你与 AI 交谈时，它所“知道”的信息。如果你想问 AI 一个问题：“根据目前的线索，谁最有可能犯下了这起罪行？”，你需要向它提供关于所有嫌疑人的信息。
*   如果没有分类，你就必须一个接一个地手动选中（@）每一个嫌疑人。
*   有了分类，你只需选择 **+ Context -> Category: Suspects（分类：嫌疑人）** 即可。

这会**一次性**将所有关于这些条目的信息发送给 AI。如果你以后在写作中把一个新路人变成了嫌疑人（给他加了标签），他就会被自动包含进你的下一次关于嫌疑人的 AI 聊天中。

**总结**
你现在已经学习了如何创建自定义分类、如何使用标签和 Codex 详情自动聚拢条目，以及如何随着故事的发展管理和更新你的分类。

### 关键概念与底层机制解析

本节课介绍的“分类（Categories）”是 Novelcrafter 中将静态资料库转化为**动态写作引擎**的核心机制。以下是隐藏在操作背后的高级写作逻辑：

**1. 刚性“类型 (Type)”与柔性“分类 (Category)”的正交关系**
*   **概念**：在底层数据库逻辑中，“类型 (Type)”是本体论的（一个东西要么是人，要么是地点，这叫 Type），而“分类 (Category)”是逻辑关联的。
*   **应用**：一个叫做“盗贼公会”的分类，不仅可以包含公会长、小偷等 **“角色”**，还可以包含下水道基地等 **“地点”**，以及开锁器、公会徽章等**“物品”**，甚至是公会黑话等 **“术语”**。这种跨类型（Cross-type）的分组，完美契合了小说的网状网格设定。

**2. 宏观上下文注入 (Macro Context Injection)**
*   在与 AI 共同探讨情节时，AI 面临的最大问题是“信息碎片化”。如果你只给 AI 看了公会长的卡片，AI 就不知道公会基地的设定。
*   **机制突破**：通过引入“分类”，你可以向 AI 一键注入整个 **“生态系统”**（比如包含人、物、地点的“里弗斯家族”）。这就等于塞给 AI 一本极其详尽的微型维基百科。AI 掌握了错综复杂的家族关系和共有财产，从而能推理出更深刻、更符合逻辑的剧情建议。

**3. 动态更新与自动化工作流 (Dynamic Context)**
*   文中提到的“方法 2”极其巧妙。它建立了一个自动化的规则（Automation Rule）。
*   **神仙用法**：假设你的设定集里有一个下拉菜单叫“当前阵营”。你的主角原本在“反抗军”，后来叛变到了“帝国军”。你只需要在角色的详情里把下拉菜单从“反抗军”改成“帝国军”。
    *   因为你设置了联动，这个角色会自动从“反抗军分类”中消失，并加入“帝国军分类”。
    *   下一次你让 AI 总结“目前帝国军有多少战力”时，AI 会自动把你叛变的主角算进去，**你不需要手动去改任何 AI 的提示词**。这极大降低了中长篇小说的“设定维护成本”。

**4. 系列级知识共享 (Series-level Knowledge Base)**
*   作者提到的“额外提示”。如果你在写《哈利波特》那样的七部曲，第一部里的“格兰芬多（分类）”可以直接继承到第二部、第三部。这就构成了行业里常说的 **“Story Bible（故事圣经）”**。在 Novelcrafter 里，AI 可以无缝读取多卷本之间的通用设定池，保证了系列小说的背景连贯性。
