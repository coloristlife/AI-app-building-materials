## 剧情发展 / 增量设定 （Progressions/Additions）

如果角色在故事中途突然被附身，怎么办？

或者：

角色的脸上后来出现了一道明显的伤疤？

你当然希望把这些变化添加到 **Codex（设定库）条目** 中，以便 AI 之后能够记住这些信息。

但是，你也知道：

如果你在创建 Codex 时就提前把这些信息加入进去，AI 可能会在剧情还没有发展到那里之前，就提前提到这道伤疤。这就造成了时间线错误（timeline inconsistency）。


这段文字实际是在引出 Novelcrafter Codex 的一个功能：**Progressions（剧情发展/阶段性更新）**。Novelcrafter 后续增加了 Progressions（剧情发展/阶段性更新），可以让某个 Codex 信息只在故事推进到特定阶段后生效，而不是从一开始就让 AI 知道。([NovelCrafter Feedback][1])

例如：

初始 Codex（设定库）：

```
方明

外貌：
38岁，黑发，没有明显伤痕。
```

然后添加一个 Progressions（剧情发展/阶段性更新）：

```
触发时间：
第三幕 / 实验事故之后

变化：
脸部留下明显烧伤疤痕。
```

效果：

第一章：

```
方明的脸上没有伤痕。
```

第三幕后：

```
方明脸上的伤疤成为他的标志。
```

所以 Codex 不应该只是：  “角色最终状态数据库” 。而应该是： “随着剧情推进而变化的动态故事数据库”。

这也是为什么 Novelcrafter 的 Codex 不只是人物卡，而更接近一**个能随时间演进、具备版本控制能力的“故事圣经（Story Bible）与世界观引擎”。**


# 如何创建 设定演变 （Codex Progression）？

https://www.novelcrafter.com/help/docs/codex/progressions-codex-details

你必须在**写作/手稿界面（Write Interface触发它，而不是在 Codex 界面里。

1. **进入场景**：进入左侧的 **Write**（写作）面板，打开剧情中“角色/物品设定发生改变”的那一个具体场景（Scene）。
2. **使用斜杠命令**：在编辑器中新起一个空白行，输入斜杠符号 `/` ，调出快捷菜                             ：在弹出的菜单中向下滚动，选择 **Codex Progression**（有的版本可能显示为  **Progressions (发展/演进)**、**Tracking (追踪)**、**Mentions (提及/关联)** **选择细节（可选）**：你是想改变角色的整体介绍，还是某一个具体的自定义细节（比如“阵营”或“外貌”）。
   * **输入新内容**：写下新的设定（例如：“在这场战斗中失去了右臂”或“角色得知了家族的秘密”）。
   * **追加 vs 替换**：在右上角的动作菜单（⚙️ 或三个点）                ，你可以选择默认的 **Addition（追加内容）**，或者选择 **Replace（完全替换掉旧设定）**。

### 2. 创建之后，在哪里可以查看它？
只有当你通过上述步骤在文章中“种”下了一个 Progression（演变记录）并保存后，你可以在以下两个地方直观地查看它：

* **在对应的 Codex（设定集）中**：现在你回到 Codex 打开那个角色的条目，你会发现在原来的基础设定下方，多出了一个 Progression 区块。它会带着一个小标记，提示你**“这个设定是从第 X 章第 X 幕开始生效的”**。
* **在 Codex 矩阵视图（Matrix）中**：你还可以在网格时间线中，清晰地看到这个角色在哪个节点发生了演变。



**💡 为什么 Novelcrafter 要设计得这么隐蔽？**
这种设计的核心是为了**防止 AI 提前剧透或时空错乱**。
如果你直接在全局 Codex 里给角色写上“后期黑化了”，AI会提前写出黑化的特征。通过在具体场景里用 `/` 插入 Progression，Novelcrafter 就能精确控制 AI 的记忆：**只有当 AI 写作到了该场景及以后的章节时，它才会读取到这条新设定**。


# 链接内容的关键技术解析

Novelcrafter 的 **Codex 演变（Codex Progressions / Additions）** 功能，解决了一个传统世界观管理（或AI提示词工程）中极具痛点的核心问题：**如何在不破坏历史、不引发AI记忆混乱的前提下，让设定随着剧情发展而动态更新。**

该功能背后涉及的核心技术与设计机制包括：

#### 1. 基于时间轴的增量记录与状态回溯（Timeline-based Incremental Tracking）
* **技术原理**：传统的静态维基页面在数据被修改后会直接覆盖旧信息，导致AI或作者无法追溯角色的过去。Novelcrafter 引入了时间轴线索，允许为同一个条目（如角色外貌、物品状态、势力关系）在不同的剧情节点添加**时间戳标记**或关联特定的章节。
* **实际效果**：系统能够识别当前正文所处的时间线位置，并只向 AI 提供该时间节点下合法的、最新的角色状态（例如：主角在第10章瞎了一只眼，AI在第11章生成内容时才会获取这个新设定，而在处理第1章前回忆时依然调用旧设定）。

#### 2. 双模更新机制：叠加（Addition）与替换（Replacement）
为了精确控制状态的变迁，其底层逻辑支持两种操作：
* **Addition（叠加/追加）**：默认模式。适用于角色新增了某种属性（如：脸上多了一道疤、学会了新技能），原有属性依然有效，新设定会与旧设定共存。
* **Replacement（替换/覆盖）**：适用于旧设定彻底失效的场景（如：某件魔法物品破碎失效、角色更改了阵营或遗忘了某段记忆）。它会在逻辑上将旧的特定细节“作废（Null and void）”，用新状态将其置换，而无需手动去大改整篇底层人物卡。

#### 3. 智能上下文注入（Context Injection & Scope Control）
* **技术原理**：在与大语言模型（LLM）交互时，Novelcrafter 的 Codex 不会将整部书所有的历史变迁无脑全部塞进 Prompt（这会导致 Token 浪费和逻辑冲突）。它通过**智能检测（Smart Detection）与标签索引（Tags & Labels）**，结合“Codex Details（细颗粒度条目）”，在作者写作特定章节时，只精准切片并动态拼装当前剧情最相关的“动态演变片段”喂给 AI。
