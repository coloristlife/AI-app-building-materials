# **Codex（设定库）**

了解如何组织你的 Codex、应该包含哪些内容，以及何时向 AI 提供这些信息。



在写作过程中，**良好的组织管理至关重要**。为了帮助你记录故事中的所有重要细节，Novelcrafter 提供了 **Codex（设定库）**，帮助你轻松管理你的世界观设定。

**Codex 是一个功能强大的工具**，用于存储和管理故事中的各种核心信息，例如**角色、地点、物品**等。

它就像是你的故事资料库（或设定百科），能够集中保存所有重要的故事元素。从**角色设定**、**地点的详细描述**，到**各种物品和道具的背景信息**，Codex 都可以帮助你统一整理和随时调用。

##  别名

Mia Richards 并不是每次被提及时都会被称为 “Mia Richards”。在日常生活中，人们称她为 “Mia”；村里的小孩子们称她为 “Miss Richards”；而她最亲近的家人则称她为 “Mimi”。因此，在 Codex 条目中，我会提供以下别名（用逗号分隔）：Mia, Mimi, Miss Richards。


## 内容：关系（Relations）

**Relations（关系）**，以前称为 **Nested References（嵌套引用）**，允许你将多个 Codex 条目组织成一个关联组。

例如：

* 假设你有一个条目叫做 **“五人议会（The Council of Five）”**，你希望每当 AI 遇到“五人议会”这个名称时，能够**自动加载五位议会成员的角色设定**。
* 或者，你有两个帮派（Gang），希望 AI 始终知道每位角色分别属于哪个家族或组织。

利用 **Relations（关系）**，你可以轻松实现这种关联。

你还可以利用这一功能，让**一个条目自动引用多个相关文档**。

例如：

**“Alekabonato 世界观（Alekabonato World Building）”** 可以作为一个总入口，当它被引用时，AI 会同时获取与其关联的内容，例如：

* 国家设定（Country）
* 风俗习惯（Customs）
* 社会结构（Social Structure）
* 着装规范（Dress Codes）
* 以及其他相关设定

这样，只需要提到一次 **Alekabonato World Building**，AI 就能同时获得整个世界观所需的全部背景信息。

此外，在 Codex 条目中，你可以**双向查看关系**：

* 查看当前条目关联了哪些其他条目（子条目）。
* 查看哪些条目引用了当前条目（父条目）。

对于每一个关联的条目，你还可以：

* **调整关系方向**（例如，将父条目改为子条目，或反之）。
* **删除该关联关系**。

---

### 更符合中文创作习惯的理解

可以把 **Relations（关系）** 理解为 **"设定之间的关联"** 或 **"设定树"**。

例如：

```
世界观
├── 国家A
│   ├── 城市1
│   ├── 城市2
│   └── 贵族家族
├── 国家B
└── 五人议会
    ├── 成员A
    ├── 成员B
    ├── 成员C
    ├── 成员D
    └── 成员E
```

当 AI 引用了 **"五人议会"** 时，它可以自动获得五位成员的设定；当引用 **"世界观"** 时，也可以自动获取整个世界观下所有相关设定。这种机制不仅能减少重复引用，还能帮助 AI 更准确地理解故事中的人物、组织和世界结构。



## 系列设定库（Series Codex）

**什么是 Series Codex（系列设定库）？它与 Book Codex（单本书设定库）有什么区别？**


**Series Codex（系列设定库）** 与普通的 **Codex（设定库）** 功能基本相同，不同之处在于：

**其中的所有设定条目都会在整个系列（Series）的所有书籍之间共享。**

也就是说，你只需要创建一次设定，就可以在该系列的每一本书中直接使用，而无需为每本书重复创建相同的内容。

例如，如果你正在创作一个三部曲：

* 《第一部：觉醒》
* 《第二部：裂变》
* 《第三部：归来》

那么下面这些适合放入 **Series Codex**：

* 世界观设定
* 国家与地图
* 历史背景
* 神话体系
* 科技设定
* 长期存在的角色
* 组织、势力
* 魔法（或规则）体系

这些内容在三部作品中都是共享的，因此只需维护一份。

而每一本书各自独有的内容，则更适合放在 **Book Codex（单本书设定库）** 中，例如：

* 本书新增的人物
* 本书特有的事件
* 本书出现的新地点
* 当前章节才会涉及的线索
* 本书专属的剧情设定

---

### Series Codex 与 Book Codex 的区别

| **Series Codex（系列设定库）** | **Book Codex（单本书设定库）** |
| ----------------------- | ---------------------- |
| 整个系列共享                  | 仅当前这一本书使用              |
| 创建一次，所有书可引用             | 每本书独立维护                |
| 适合长期稳定的设定               | 适合当前作品专属设定             |
| 修改后会同步影响整个系列            | 修改只影响当前书               |

### 一句话理解

可以把它们理解为：

* **Series Codex = 系列级设定库（所有作品共享）**
* **Book Codex = 单书级设定库（仅当前作品使用）**

这种设计既避免了重复维护相同设定，也能让整个系列保持一致性，同时保留每一本书独有的内容。


## 设定演变 / 增量设定 （Progressions/Additions）




### 如果角色在故事中途突然被附身，怎么办？

或者：

角色的脸上后来出现了一道明显的伤疤？

你当然希望把这些变化添加到 **Codex（设定库）条目** 中，以便 AI 之后能够记住这些信息。

但是，你也知道：

**如果你在创建 Codex 时就提前把这些信息加入进去，AI 可能会在剧情还没有发展到那里之前，就提前提到这道伤疤。**

---

### 更自然的中文表达：

比如：

你的角色 **方明**：

故事前半部分：

> 方明没有任何明显外伤。

到了第三幕：

> 方明经历一次实验事故，脸上留下了一道永久性伤疤。

如果你一开始就在 Codex 里写：

> 方明右脸有一道深刻的伤疤。

那么 AI 在第一章描写方明时，可能就会写：

> “方明摸了摸脸上那道伤疤……”

但此时剧情中伤疤还没有出现，这就造成了**时间线错误（timeline inconsistency）**。

---

这段文字实际是在引出 Novelcrafter Codex 的一个功能：**Progressions（设定变化/阶段性更新）**。Novelcrafter 后续增加了 Progressions，可以让某个 Codex 信息只在故事推进到特定阶段后生效，而不是从一开始就让 AI 知道。([NovelCrafter Feedback][1])

例如：

初始 Codex：

```
方明

外貌：
38岁，黑发，没有明显伤痕。
```

然后添加一个 Progression：

```
触发时间：
第三幕 / 实验事故之后

变化：
脸部留下明显烧伤疤痕。
```

效果：

第一章：

```
方明的脸上没有伤痕。
```

第三幕后：

```
方明脸上的伤疤成为他的标志。
```

---

对于你之前设计的《醒来》软科幻小说，这个功能非常重要。

因为你的故事里有大量**状态变化**：

例如：

### 方明

初始：

```
身份：
普通工程师
```

变化：

```
第40章：
发现自己可能是意识复制体
```

---

### 复制意识B

初始：

```
隐藏意识
```

变化：

```
高潮：
夺取身体控制权
```

---

### 科技设定

初始：

```
意识复制实验不存在公开记录
```

变化：

```
后期：
发现政府早已掌握该技术
```

---

所以 Codex 不应该只是：

> “角色最终状态数据库”

而应该是：

> “随着剧情推进而变化的动态故事数据库”。

这也是为什么 Novelcrafter 的 Codex 不只是人物卡，而更接近一个**可随剧情演化的故事知识库**。([novelcrafter.com][2])

在 Novelcrafter 中，如果你在左侧导航栏或者直接打开 Codex（设定集）面板时找不到 **Codex Progression（设定演进/动态设定）**，这是非常正常的。

因为 **设定演变 （Codex Progression）并不是一个独立的全局菜单，而是和“具体的故事时间线（Scene）”强绑定的**。

如果你想创建或查看 Progression，请按照以下步骤操作：

### 1. 如何创建 设定演变 （Codex Progression）？

https://www.novelcrafter.com/help/docs/codex/progressions-codex-details

你必须在**写作/手稿界面（Write Interface）**中去触发它，而不是在 Codex 界面里。

1. **进入场景**：进入左侧的 **Write**（写作）面板，打开剧情中“角色/物品设定发生改变”的那一个具体场景（Scene）。
2. **使用斜杠命令**：在编辑器中新起一个空白行，输入斜杠符号 `/` ，调出快捷菜单。
3. **选择功能**：在弹出的菜单中向下滚动，选择 **Codex Progression**（有的版本可能显示为 *Codex Addition*）。
4. **填写动态设定**：此时编辑器里会插入一个功能框。在这里你需要：
   * **选择对象**：选定发生改变的 Codex 条目（比如某个角色）。
   * **选择细节（可选）**：你是想改变角色的整体介绍，还是某一个具体的自定义细节（比如“阵营”或“外貌”）。
   * **输入新内容**：写下新的设定（例如：“在这场战斗中失去了右臂”或“角色得知了家族的秘密”）。
   * **追加 vs 替换**：在右上角的动作菜单（⚙️ 或三个点）中，你可以选择默认的 **Addition（追加内容）**，或者选择 **Replace（完全替换掉旧设定）**。

### 2. 创建之后，在哪里可以查看它？
只有当你通过上述步骤在文章中“种”下了一个 Progression 之后，它才会在用户界面中显现出来：

* **在 Codex（设定集）中**：现在你回到 Codex 打开那个角色的条目，你会发现在原来的基础设定下方，多出了一个 Progression 区块。它会带着一个小标记，提示你**“这个设定是从第 X 章第 X 幕开始生效的”**。
* **在 Matrix（故事大纲矩阵）中**：打开 Matrix 视图，你可以在角色的网格时间线中，清晰地看到这个角色在哪个节点发生了演变。

---

**💡 为什么 Novelcrafter 要设计得这么隐蔽？**
这种设计的核心是为了**防止 AI 提前剧透或时空错乱**。
如果你直接在全局 Codex 里给角色写上“后期黑化了”，AI 在帮你续写第一章时，可能就会提前写出黑化的特征。通过在具体场景里用 `/` 插入 Progression，Novelcrafter 就能精确控制 AI 的记忆：**只有当 AI 写作到了该场景及以后的章节时，它才会读取到这条新设定**。
