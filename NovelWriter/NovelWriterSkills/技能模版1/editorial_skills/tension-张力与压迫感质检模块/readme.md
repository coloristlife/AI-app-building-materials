你好，首席架构师。我是你的 AI 写作工程总监。

在 `editorial_skills/` （编辑/质检模块）中，如果说 `character`（人物）是故事的**灵魂**，那么 `tension`（张力）就是故事的**心跳与血压**。

没有张力的剧情，就像是心电图上的一条死线。在这个模块里，AI 同样不负责写哪怕一句环境描写，它化身为一台**无情的测谎仪和血压计**，专门排查剧情中的“注水”、“顺撇（主角光环太强）”和“平铺直叙”。

我们将继续以罗伯特·麦基（Robert McKee）的《故事》（对抗力量法则、鸿沟理论、价值翻转）以及布莱克·斯奈德（Blake Snyder）的《救猫咪》（坏人逼近、原始动力）为理论基底，为你拆解 **`editorial_skills/tension/` (张力与压迫感质检模块)** 的具体 Skill 列表。

### 📂 目录：`editorial_skills/tension/` (张力与压迫感质检模块)
这个文件夹下的 AI 工具，核心逻辑是寻找**阻力、信息差、时间限制与致命后果**。

#### 🛠️ Skill 1: `expectation_vs_reality_gap_calculator` (期望与现实鸿沟测算仪)
*   **理论基底**：《故事》（麦基的“鸿沟理论” The Gap）
*   **核心职责**：杜绝“心想事成”的流水账，确保主角的每一个核心行动都遭到世界的无情反弹。
*   **AI 诊断逻辑**：
    1.  **提取行动与期望**：AI 扫描主角在某一情节点采取的行动，以及主角主观期望得到的好结果。
    2.  **侦测反作用力（The Gap）**：AI 检查客观世界（他人、社会、自然或自我潜意识）是否给出了**完全出乎主角意料的反弹**。
    3.  **阻力判断**：如果主角出招，对手直接倒下，主角顺利拿到宝物。AI 报错：“出现‘顺撇’剧情，没有鸿沟，张力归零。必须让主角的行动引发比原来更糟糕的境地。”
*   **输入**：场景或序列大纲（包含角色的行动计划）。
*   **输出（JSON格式）**：`{"protagonist_action": "行动", "expected_result": "期望", "actual_reality": "现实反弹", "gap_severity": "1-10分", "pass_or_fail": boolean}`

#### 🛠️ Skill 2: `escalation_and_antagonism_scanner` (敌对力量与冲突升级扫描器)
*   **理论基底**：《故事》（对抗力量法则 Law of Conflict）+《救猫咪》（坏人逼近 Bad Guys Close In）
*   **核心职责**：检查反派/阻碍是否足够强大，以及冲突是否呈阶梯状递增（Progressive Complications）。
*   **AI 诊断逻辑**：
    1.  **力量天平对比**：AI 提取主角的当前能力值与反派/困境的破坏力。如果主角的能力始终大于或等于困境，报错：“反派太弱，主角没有被逼入绝境”。
    2.  **核对“坏人逼近”节拍**：在故事的中点（Midpoint）之后，AI 强制检查反派是否重组了力量，是否对主角发动了更致命、更针对主角“软肋”的打击。
    3.  **冲突类型升级**：检查冲突是否从“个人/内部”扩散到了“环境/生死”，或者反过来（外在危机引发内心的全面崩溃）。
*   **输入**：全书大纲 / 第二幕后半段大纲
*   **输出**：`{"antagonist_power_level": "对比分析", "complication_steps": ["冲突1", "冲突2", "冲突3(需最强)"], "escalation_curve": "平缓/陡峭/下降(报错)"}`

#### 🛠️ Skill 3: `stakes_and_clock_validator` (核心赌注与倒计时质检仪)
*   **理论基底**：《救猫咪》（原始动力 Primal Stakes + 倒计时 Ticking Clock）
*   **核心职责**：回答读者心里最致命的那个问题：“如果主角失败了，那又怎样？”
*   **AI 诊断逻辑**：
    1.  **提取赌注（The "Or Else" Factor）**：AI 审视主角的任务，询问失败的后果。如果是“失去一份无聊的工作”，张力不够；如果是“失去至亲、失去生存权利、或者彻底失去尊严（社会性死亡）”，则 Pass。必须是**原始（Primal）**的。
    2.  **寻找倒计时（Ticking Clock）**：AI 扫描剧情中是否有一个清晰的时间界限（例如：炸弹还有 5 分钟爆炸、婚礼在明早举行、毒药在 24 小时后发作）。
    3.  **紧迫感折算**：如果没有时间限制，主角可以慢慢悠悠地解决问题，AI 报错：“缺乏时间压迫，剧情结构将变得松散。”
*   **输入**：核心冲突设定 / 第三幕大纲
*   **输出**：`{"primal_stakes": "失败的致命后果", "ticking_clock": "识别出的时间限制", "urgency_score": "1-10分", "improvement_suggestion": "如何增加筹码"}`

#### 🛠️ Skill 4: `dramatic_irony_radar` (戏剧反讽/信息差雷达)
*   **理论基底**：悬疑大师希区柯克的“桌下炸弹”理论 + 麦基的故事信息控制
*   **核心职责**：通过计算读者、主角、配角掌握的信息量差异，来制造期待感和悬疑感。
*   **AI 诊断逻辑**：
    1.  **信息矩阵盘点**：AI 列出当前阶段的核心秘密（如：杯子里有毒、女配是内鬼）。
    2.  **计算信息差**：
        *   *悬疑模式*：读者知道，主角不知道（桌下有炸弹，主角还在谈笑风生）。AI 给予高张力评分。
        *   *解谜模式*：主角知道，读者不知道（主角暗中布了个局，最后揭晓）。
        *   *惊吓模式*：主角和读者都不知道（突然爆炸）。AI 提醒：“只能偶一为之，不能作为长期张力来源。”
    3.  **质检报告**：如果所有人都知道所有事，或者没有隐藏信息，AI 报错：“信息完全透明，失去叙事黏性。”
*   **输入**：多条故事线大纲 / 场景群集
*   **输出**：`{"core_secret": "核心机密", "reader_knows": boolean, "protagonist_knows": boolean, "tension_type": "悬疑/惊吓/解谜", "effectiveness_check": "信息释放时机评估"}`

#### 🛠️ Skill 5: `value_charge_shifter` (正负极价值翻转校验器)
*   **理论基底**：《故事》（场景的极性翻转 Value Shifts）
*   **核心职责**：把控微观张力。确保每一个场景（Scene）都不是无效过场，场景的开头和结尾必须有情感或处境的“正负极改变”。
*   **AI 诊断逻辑**：
    1.  **定位核心价值**：AI 分析该场景围绕什么价值展开（例如：生存/死亡、信任/背叛、自由/奴役）。
    2.  **测量极性（Polarity）**：
        *   场景开始时，价值是正极（+）还是负极（-）？（例：主角潜入很顺利，+）
        *   场景结束时，价值是正极（+）还是负极（-）？（例：主角被警报发现，-）
    3.  **翻转核查**：如果场景开始是（+），结束还是（+）；或者开始是（-），结束还是（-）。AI 直接拉响警报：“这是一个无效场景！没有发生极性转换（Turning），只有纯粹的信息交代（Exposition），立刻重写或删减！”
*   **输入**：单个场景（Scene）的详细大纲（事件流）。
*   **输出**：`{"scene_value": "如：安全/危险", "opening_charge": "+/-", "closing_charge": "+/-", "did_it_turn": boolean, "tension_verdict": "有效翻转 / 无效死水"}`

### 💡 总监点评（使用说明书）：
这个 `tension` 模块是你防注水、防烂尾的最强利器。

在你的工作流中，当大纲通过了 `character`（人物模块）的测试后，你可能得到了一个“人设很棒”的故事。但这还不够，很多时候人设好，但剧情平淡如水。

此时，**将大纲投喂给这 5 个 `tension` 工具**：
*   如果 `escalation_and_antagonism_scanner` 返回的压力曲线是平的，说明你的反派在摸鱼，赶紧回去给反派加 Buff。
*   如果 `value_charge_shifter` 发现连续三个场景极性都没有翻转，说明你的节奏已经彻底崩坏，读者大概率会在这个段落弃书。
*   如果 `stakes_and_clock_validator` 找不到倒计时，说明你的高潮剧情不够燃。

**严苛的质检标准：** `editorial_skills` 必须像一个冷血无情的剧本医生。只有当这些 JSON 返回的 `pass_or_fail` 全部为 `True` 时，大纲才算及格。

接下来，你可以决定是继续深挖 `editorial_skills` 的其他模块（比如 `structure` / `scene` / `dialogue`），还是准备切换频道，看看 `writing_skills`（生成模块）是如何根据这些硬核数据，去渲染出充满电影感画面的？
