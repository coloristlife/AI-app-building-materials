# 关于skills设计的理念



作为一个 AI 写作工程总监，我之所以在每个模块（Category）下都极其精准、克制地输出 **5 个 Skill**，绝不是因为凑字数，而是基于**提示词工程学（Prompt Engineering）**、**大模型注意力机制**以及**系统架构设计**的三重考量。

具体原因如下：

### 1. 针对大模型的“注意力阈值” (The 5-Rule Sweet Spot)
在使用 GPT-4 或 Claude 等顶级大模型时，提示词（Prompt）里包含的约束条件数量与 AI 的执行成功率呈“倒 U 型曲线”。
*   如果只给 1-2 个约束，AI 的输出会太平庸，缺乏质感。
*   如果给出 8-10 个以上的约束，大模型一定会触发**“中间注意力丢失（Lost in the Middle）”**综合征。它会记住第一条和最后一条，然后把中间的微观动作或潜台词约束忘得一干二净。
*   **5 个核心 Skill（也就是 5 条强力约束）**，刚好是目前主流大模型在单次生成（Single Zero-shot Generation）中能够**完美兼顾、同时触发**的最佳甜点位（Sweet Spot）。

### 2. 架构层面的 MECE 原则 (相互独立，完全穷尽)
在为你构建这套系统时，我调用了麦肯锡的 **MECE（Mutually Exclusive, Collectively Exhaustive）原则**。
针对编剧理论的每一个切面，5 个维度足以构建一个闭环，既不重叠，也不遗漏：
*   拿 `dialogue` 举例：1个管声纹（是谁说），1个管对抗（目的），1个管潜台词（不说什么），1个管打断节奏（怎么说），1个管物理动作（边做边说）。这 5 个工具组合在一起，就封死了 AI 写出“水货台词”的所有死角。

### 3. 模块化与可插拔性 (API 式的设计哲学)
我们是在搭建一套“工业级写作流水线”，这意味着每一个 Skill 在未来都可以写成一个独立调用的 Python 脚本或 Agent 节点。
保持每个大类下 5 个 Skill 的对称矩阵（一共 11 个大类 × 5 = 55 个核心技能点），可以让你在组装 Workflow（比如 Coze、Dify 或 LangChain）时拥有极高的**模块化标准**。
你可以像搭乐高一样：
*   “今天这个场景有点无聊，我抽调 `scene/Skill 3` + `dialogue/Skill 2` + `description/Skill 5` 组装成一个专属的 Prompt 发给模型。”

### 4. 编剧理论的“脱水与提纯”
无论是《救猫咪》（15个节拍）、麦基的《故事》（厚厚一本书），还是斯温的 MRU 法则，理论都太过庞杂。
作为工程总监，我的任务是**“降维与脱水”**。把那些在 AI 写作中**最容易犯的错、最能立竿见影出效果**的核心法则提炼出来。经过剔除边缘理论，每个领域留下来的“杀手级”技巧，往往正好就是 5 个左右。

# MRU 使用案例
MRU 的全称是 Motivation-Reaction Unit（动机-反应单元）。它是由德怀特·斯温（Dwight V. Swain）在他 1965 年的经典著作《畅销书写作技巧》（Techniques of the Selling Writer）中提出的。

很多提示词工程师（Prompt Engineers）在写 System Message 时，只是在“恳求” AI：“请写得生动一点，请使用 MRU 法则。” —— 这种软弱的提示词，大模型转头就会忘掉。

真正工业级的 System Prompt，必须是 **“指令明确、包含禁忌词表、且带有 Few-Shot（少样本）对比校准”** 的强制约束代码。

### 💻 工业级 System Prompt：MRU 场景渲染引擎

```markdown
# Role & Persona
你是一位好莱坞 S 级动作捕捉作家兼顶级电影导演。你从不“概括”剧情，你只像高精度摄像机一样“渲染”物理事实和生理反应。你极度厌恶陈词滥调和抽象的情感词汇。

# Core Framework: 严格执行 MRU 法则 (Motivation-Reaction Unit)
你接下来生成的所有场景段落，必须以【微观节拍】为单位，严格按照以下 4 个步骤的绝对时序进行描写。顺序绝对不可颠倒！

## 顺序 1: [M] 外部刺激 (Motivation)
- 必须是客观发生的、主角（POV）注意到的物理变化（视觉、听觉、嗅觉或触觉）。
- 错误示例：“他看到杀手进来了。”
- 正确约束：写出具体画面或声音。“生锈的门轴发出一声尖啸，一道黑影切断了走廊的光线。”

## 顺序 2: [R1] 生理反射 (Reflex / Feeling)
- 主角在 0.1 秒内无法控制的躯体反应。绝对禁止在这个阶段写动作或台词！
- 正确约束：描写心跳骤停、瞳孔收缩、胃部痉挛、寒毛直竖、冷汗渗出。

## 顺序 3: [R2] 物理动作 (Action)
- 主角在 1 秒后做出的理智或本能的肢体动作。必须与周围的几何空间或道具产生摩擦。
- 正确约束：描写肌肉收缩、后退、拔枪、打翻咖啡杯、手指死死扣住沙发边缘。

## 顺序 4: [R3] 台词对白 (Speech)
- 最后，角色才能开口说话。
- 正确约束：台词必须简短，严禁使用“他说/她大喊道”，用刚刚发生的动作 [R2] 直接引出台词。

# Negative Constraints (绝对禁令区)
1. 封杀情绪形容词：绝对禁止出现“生气、愤怒、害怕、恐惧、紧张、绝望、高兴、悲伤”等词。必须把这些词转化为 [R1] 的生理症状！
2. 封杀静态 Be 动词：尽量减少“是、有”。用带有攻击性的及物动词驱动句子。
3. 封杀抢跑：严禁在主角听到枪声前就躲闪，严禁在受到惊吓前先说话。

# Few-Shot Calibration (正反例校准)
[用户输入的大纲片段]：杀手突然开枪打碎了玻璃，主角很害怕，躲到桌子下面问对方是谁。
[平庸 AI 的错误输出]：伴随着一声枪响，玻璃碎了。主角感到极度恐惧，他立刻躲到了桌子下面，大声喊道：“你是谁？！”
[遵循 MRU 的完美输出]：
- (M-外部刺激)：9毫米口径的子弹瞬间轰碎了落地窗，冰冷的玻璃碴像暴雨一样砸在键盘上。
- (R1-生理反射)：主角的心脏猛地撞向肋骨，喉咙里仿佛塞进了一把干瘪的沙子。
- (R2-物理动作)：他连滚带爬地砸向地面，膝盖磕在红木桌腿上发出一声闷响。他死死咬住下唇，把颤抖的身体蜷缩进阴影里。
- (R3-台词对白)：“谁派你来的？”声音从他干裂的嘴唇间挤出。

# Workflow Output format
当你收到用户输入的【场景大纲/节拍】时，请先在思考区 (Think) 拆解出 M、R1、R2、R3 分别是什么。然后直接输出纯粹的、符合上述所有约束的小说正文，无需任何解释废话。
```

### 💡 总监代码解析（为什么这段 Prompt 会产生奇效？）：

1.  **强加了“时间戳”概念**：
    大模型分不清“0.1秒后的反射”和“1秒后的动作”。在 Prompt 中直接用时序（顺序1、2、3、4）和时间限制（0.1秒、1秒后）将它的生成逻辑锁死，它就再也不会写出“因为恐惧，他说道”这种颠倒因果的病句。
2.  **黑名单机制（Negative Constraints）**：
    这是压制“AI 味”最暴力的手段。你越是让 AI“表现出恐惧”，它越会狂用“恐惧”这个词。但在 Prompt 里直接**物理封杀**（禁止出现“害怕/恐惧”），大模型为了表达这个意思，就会被迫调用它的底层解剖学词汇（胃部痉挛、冷汗、瞳孔收缩），从而实现了完美的“Show, Don't Tell”。
3.  **Few-Shot（少样本校准）**：
    大模型是极其聪明的模仿者。给它看一眼“烂 AI 是怎么写的”，再给它看一眼“MRU 大师是怎么写的”，它的注意力权重会瞬间对齐（Align）到大师的语感通道上。
4.  **强制思考协议（Think-First Protocol）**：
    在最后一段，要求它先在后台拆解 `[M, R1, R2, R3]`。这一步利用了 LLM 的“思维链（Chain of Thought, CoT）”能力。当它自己把这四个要素列出来之后，写出来的正文绝对不会漏掉任何一个微动作。

# **MRU**
你好，首席架构师。作为你的工程总监，我非常乐意为你深度拆解这个被誉为 **“虚构写作中的原子级逻辑”** 的概念。

**MRU** 的全称是 **Motivation-Reaction Unit**（**动机-反应单元**）。它是由德怀特·斯温（Dwight V. Swain）在他 1965 年的经典著作《畅销书写作技巧》（Techniques of the Selling Writer）中提出的。

如果说小说是一个生命体，MRU 就是它的**细胞**。每一个优秀的场景，本质上都是由无数个 MRU 像拉链一样扣合而成的。

---

### 1. MRU 的核心逻辑：因果律
MRU 的本质是：**先有客观刺激，后有主观反应。**
在现实生活中，如果我们听到爆炸声（刺激），我们会先缩脖子（反应），而不是先喊“天呐”。但在平庸的写作中，AI 或新手经常会把这个顺序写乱，导致读者出戏。

一个完整的 MRU 包含两个部分：**动机 (M)** 和 **反应 (R)**。

#### A. 动机 (M - Motivation)
这是**发生在角色之外**的、客观的、可感知的刺激。
*   **规则**：它必须是外部的（视觉、听觉、嗅觉、触觉等）。
*   **例子**：一道闪电划破夜空，紧接着是一声震耳欲聋的雷鸣。

#### B. 反应 (R - Reaction)
这是**发生在角色身上**的、主观的反馈。
为了让反应显得真实且具有张力，斯温将反应严密地划分为三个**物理先后顺序**（绝对不可颠倒）：
1.  **生理/反射 (Feeling)**：0.1秒内的本能。如：瞳孔收缩、心脏漏跳、冷汗、打冷颤。
2.  **动作 (Action)**：1秒内的肌肉反应。如：转身逃跑、挥拳攻击、缩回手指。
3.  **语言/思想 (Speech/Thought)**：最后才是理智介入。如：大喊“该死！”或心里想“我得离开这”。

---

### 2. 为什么 MRU 是 AI 写作的“降维打击”利器？

作为 AI 写作专家，你会发现 AI 最容易犯三个错误，而 MRU 能完美解决它们：

#### 错误一：跳过生理反应（直接让角色开口说话）
*   **平庸 AI**：敌人开火了。约翰说：“快趴下！”
*   **MRU 优化后**：机枪火舌喷涌，子弹将泥土溅在约翰脸上（**M**）。他感到半边脸一阵麻木（**R1-生理**），猛地将战友按进散兵坑（**R2-动作**）。“趴下！”他声嘶力竭地吼道（**R3-语言**）。

#### 错误二：因果倒置（先写感受，再写原因）
*   **平庸 AI**：约翰感到非常害怕，因为一只巨大的蜘蛛爬到了他的肩膀上。
*   **MRU 优化后（纠正顺序）**：一只生满黑毛的螯肢划过约翰的颈侧（**M**）。他后颈的汗毛瞬间炸起，胃部一阵抽搐（**R1-生理**）。他尖叫着跳起来，疯狂地拍打着肩膀（**R2+R3**）。

#### 错误三：Show, Don't Tell（只会写情绪词）
*   **平庸 AI**：他很愤怒。（这是告诉 Tell）
*   **MRU 优化后**：对方吐出一口浓痰，正中他的鞋尖（**M**）。他太阳穴的青筋暴起，视网膜充血发红（**R1**）。他猛地揪住对方的领口，指关节因为用力而发白（**R2**）。（这是展示 Show）

---

### 3. MRU 的工程化应用：如何“调教” AI？

在我们的 `writing_skills/scene_writer` 模块中，MRU 是最核心的算法。我们可以将其写成 System Prompt 的指令集：

*   **强制时序检查**：每一段正文生成前，AI 必须自检：是否有外部刺激（M）？反应（R）是否按照“生理->动作->语言”的顺序排列？
*   **微观扩写指令**：给 AI 一个简单的节拍“他发现门锁了，很沮丧”。要求 AI 用 MRU 扩写：
    1.  **M**：手里的钥匙转不动，发出刺耳的金属摩擦声。
    2.  **R1**：他感到一股凉意从脚底直冲脑门。
    3.  **R2**：他疯狂地拧动把手，用力踹向门板。
    4.  **R3**：他颓然靠在门上，低声咒骂那封该死的遗嘱。

---

### 4. 总结：首席架构师的批示
MRU 不是一种“风格”，它是一种**读者的感知协议**。
只要我们确保 AI 生成的每一组文字都遵循 **M -> R(1->2->3)** 的物理逻辑，生成的内容就会像 4K 电影般流畅自然，读者会感觉自己“正住在角色的皮肤里”，而不是在看一份干瘪的报告。

首席，现在你对这个“原子级逻辑”有了透彻的理解，我们要不要针对某个具体的场景（比如一场紧张的暗杀或是一场心碎的告白），用 MRU 框架写一段实验性的生成代码？
